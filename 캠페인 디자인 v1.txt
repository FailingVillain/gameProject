작성 2026-10-22 · 사용자와 Claude 논의용 · 확정 표기가 없는 것은 모두 제안

- 구판(docs/캠페인-초안.txt, 두만강 · 간도 21미션안)은 폐기. 참고만 한다.
- 기존 자료의 위치:
    세계관 · 인물   korean-division/docs/SETTING_NOTES.md (기준), CHARACTERS.md
    홈 · 자원 규칙  korean-division/docs/CAMPAIGN_HOME_DESIGN.md
    스토리 원문     korean-division/스토리 설계 - 초안.txt
    옛 에피소드표   game-tools/campaign/EPISODES.md (이 문서가 대체 예정)

1. 용어 (사용자 확정 2026-10-22)
==================================================================
계층:  Chapter(챕터) > Episode(에피소드) > Mission(미션, 총칭)
       Chapter = 가장 큰 단위 (묶음). Episode = 실질 구현 · 설계 단위 (사용자 2026-10-22).
       따라서 층 1 흐름도 · 층 2 명세는 Episode 단위로 파일을 나눈다.

Mission 의 등급
  Operation (대형 작전)  기존 "큰 교전".   1~2시간. 에피소드의 중심.
  Battle    (중형 작전)  기존 "서브 미션 / 중형". 30~45분.
  Skirmish  (소형 작전)  기존 "소형".      10~20분.

Mission 이 아닌 노드 (흐름도에만 존재)
  Choice    (선택지)     비용 · 호감도 · 해금이 걸린 결정. 전투 없음.
  Event     (사건)       대사 · 본국 명령 · 인물 등장 · 조건부 변화. 전투 없음.
  Interlude (홈 구간)    캠페인 홈에서 편성 · 보충 · 외교를 하는 구간.

속성 (등급과 별개 — 등급이 필수/선택을 결정하지 않는다)
  required : 필수(true) / 선택(false)
  패배 규칙 [확정 2026-10-22]: Operation · Battle = 재도전(대가 없음).
             Skirmish = 패배 시 "재도전 / 실패 확정" 선택 (선택 Skirmish 만. 필수 Skirmish 는 재도전만).
             실패 확정 시 보상을 놓치고 on_lose 의 변수 · 플래그가 적용된다.
             미션별로 덮어쓸 수 있다.
  기본 패배: 쓰러진 병사(사망+부상) 50% 이상 (변수 maxCasualtyFrac, 미션별 덮어쓰기 가능).

주의: 코드 · 기존 문서의 "mission"(MissionResults, 미션 파일)은 이미 총칭이므로
      새 용어와 일치한다. 기존 문서의 "큰 교전/중형/소형"은 Operation/Battle/Skirmish 로 읽는다.

2. 층 구조 (2층 확정 + 3층 대비)
==================================================================
공통(층 0): 변수 레지스트리 (§3) — 모든 층이 같은 변수 이름을 참조한다. 한 곳에서만 정의.

층 1  흐름 (Flow)   — 설계 논의의 중심. 사용자 + Claude 가 함께 쓴다.
      "무엇이 어떤 순서 · 조건으로 이어지나."
      노드(Operation/Battle/Skirmish/Choice/Event/Interlude) + 간선(조건 · 승패) + 변수 증감.
      분량: 챕터당 한 문서, 에피소드당 한 화면 분량.

층 2  명세 (Spec)   — 구현용. 주로 Claude 가 층 1 에서 파생해 채우고 사용자가 검수.
      "이 미션은 어떻게 만들어지나."
      지도 생성 파라미터 · 편성 · 적 · 목표 · 이벤트 트리거 · 보상.
      층 1 의 노드 ID 하나에 명세 블록 하나.

층 3  연출 (Script) — 지금은 만들지 않는다. 층 1/2 가 안정된 뒤 분리할 후보.
      "플레이어에게 무엇이 보이고 들리나."
      브리핑 · 쪽지 · 대사 · 포트레이트 · 전보 · 훈수 문구 · 엔딩 텍스트.
      지금은 층 2 의 script 칸에 한 줄 요약(의도)만 적고, 실제 문장은 층 3 에서 쓴다.
      분리 시점 기준 (제안): 층 2 의 대사 · 쪽지 분량이 미션당 10줄을 넘기 시작하면.

파일 배치 (제안)
  gameProject/캠페인 디자인 v1.txt            이 문서 (양식 · 용어 · 변수 · 규칙)
  gameProject/campaign/vars.txt              변수 레지스트리 (층 0)   ← 만들 때
  gameProject/campaign/flow_ch0.txt, flow_ch1.txt ...   (층 1)
  gameProject/campaign/spec_ch1_e1.txt ...             (층 2, 에피소드 단위)
  (층 3 이 생기면) campaign/script_ch1_e1.txt
  ※ 지금은 이 한 파일 안에 §5~§7 로 시작하고, 분량이 늘면 위처럼 쪼갠다.

3. 변수 레지스트리 (층 0) — 초안
==================================================================
원칙: 모든 증감 · 조건은 아래 이름만 쓴다. 새 변수는 여기 먼저 등록한다.
표기: 이름 : 타입 [범위] — 의미 (출처)

[인물 호감도]  타입 int [-3..+3] (확정: 정수 단계, VIP 위주 — 사용자 2026-10-22)
  기준 0, 이벤트 단위로만 증감(보통 ±1, 큰 사건 ±2), 숫자는 UI에 직접 노출하지 않고 간접 표현 권장
  증감 값은 사용자가 정수로 직접 지정한다 (사용자 2026-10-22). 아래 ±1/±2 는 임시 기준.
  VIP 후보: 황손 · 민 대장 · 이석 · 남 참장 · 시위대장
  favor.hwangson : 황손 이태 호감 (심기). 낮으면 신병 · 보급 감소 (HOME_DESIGN §7)
  favor.minDaejang : 총사령관 민 대장 호감
  favor.yiSeok : 군단장 황자 이석 호감
  favor.namChamjang : 11사단장 남 참장 호감
  favor.siwidae : 시위대장 호감 (황손 측근)
  김주현 = 호감 변수 없음 [확정]. 장교단 일반 호감은 VIP 아님 → 필요해질 때 추가.
  morale.troops : 병사 사기 (캠페인 단위)            (스토리 초안 "병사들 사기 증진/저하")
[지역 · 외부]
  rep.local : 지역 평판 (민심)                        (스토리 초안 "지역 평판")
  intel.<대상> : 정보 획득 플래그 (예: intel.andong)  bool
[자원]  (CAMPAIGN_HOME_DESIGN §1 의 실제 자원 — 여기서는 증감 표기만 맞춘다)
  supply, recruits, funds, 탄약(구경별), 포탄(종류별)
[해금]
  unlock.<이름> : bool  (예: unlock.fieldGun, unlock.howitzer)
[분기 플래그]
  flag.<id> : bool/int  (미션 결과 · 선택지 결과 기록)

미결: 호감도 범위 · 단위를 정수 단계로 할지(제안) 연속 수치로 할지.
      "스토리 초안"의 호감/비호감은 최소 ±1 단계로 옮기고, 큰 사건만 ±2.

5. 층 1 양식 — 흐름 노드
==================================================================
한 노드 = 아래 필드. 한 줄로 쓸 수 있으면 한 줄로 쓴다.

  <ID> [상태] <종류> <이름>  (required: 필수|선택)
    where : 장소 (당대 지명)
    summary : 한 문장 (무슨 일인가)
    requires : 진입 조건 (이전 노드 · 변수 조건). 없으면 생략
    on_win  : → <다음 노드 ID>   변수 증감 / 보상
    on_lose : → <다음 노드 ID 또는 "재도전">   변수 증감
    options : (Choice 전용) 선택지별 비용 · 효과 · 호감 증감
    effects : (다른 노드에 주는 영향, 예: "C1E1-OP2 적 배치 일부 공개")
    absurd : 부조리 훅 (황손 훈수 / 민 대장 강행 명령 / 이석 정지 / 본국 제약) — 해당 시만

예시 (스토리 초안의 선택지 A1 을 이 양식으로 옮긴 것):

  C1E1-CH1 [제안] Choice 병력 보충 방침  (required: 필수)
    requires : C1E1-OP1 완료
    options :
      A 서간도 의용군 고용 — funds 소모, 의용군 +400, favor.minDaejang -1
      B 마적 초모          — funds 대량, 마적 +100~300(100단위), favor.hwangson -1, favor.minDaejang -2
      C 대민 구제          — supply 소모(상당), rep.local +1
    (선택 안 함 가능 여부: 미정)

6. 층 2 양식 — 미션 명세
==================================================================
층 1 노드 ID 와 1:1. Mission(OP/BT/SK) 노드만 가진다.
옛 EPISODES.md 블록을 이어받되, 아래 원칙으로 정리한다.

  id        : C1E1-OP1
  name      : 압록강 도하
  rank      : OP | BT | SK        required: true|false
  place     : 당대 지명
  map       : base=새로 생성 | reuse=<지도 ID>:<구역>      (중 · 소형은 가급적 reuse)
              size=tiny|small|medium|large|huge
              (지형 서술은 사용자가 구술한 만큼만 terrain 에 적는다 — 선택 칸.
               지도는 자동 생성 후 수정하는 방침이므로 비어 있어도 된다.)
  terrain   : (선택) 강 · 도시 · 철도 · 고지 · 숲 · 참호 · 철조망 위치
  player    : maxDeploy, 고정 편성(있으면), 시작 위치
  enemy     : 세력 · 규모 · 구성 · 배치/자세
  objectives: win / lose / time    (lose 기본값 = maxCasualtyFrac, 쓰면 "기본" 한 단어)
  events    : 트리거 → 결과 목록 (예: "초소 2 격파 → 마적 기병 30 출몰")
  rewards   : 변수 증감은 층 1 에서 정한 것을 따른다 (여기서 중복 정의 금지)
  script    : (층 3 예약) 의도 한 줄. 예: "김주현 쪽지: 제압 후 우회를 권함"
  notes     : 자유

효율화 규칙
  1) 기본값 상속: 같은 칸이 반복되면 §8 "기본값 표"에 한 번만 적고 미션에서는 생략.
  2) 변수 증감은 층 1 에만 쓴다. 층 2 는 층 1 노드를 참조(중복 금지).
  3) 지도 재사용: 에피소드의 Operation 지도를 기준으로 Battle/Skirmish 는 구역만 지정.
  4) 안 정해진 칸은 ? 가 아니라 [미정] 표기 후 생략 — 질문은 문서 끝 §10 한 곳에 모은다.
  5) 에피소드 헤더 표 (한눈에): 각 에피소드 맨 위에 노드 1줄 요약 표를 둔다 (예시 §7).

11. Decision (디시전) 객체 — 층 1 의 독립 항목  [양식 확정 2026-10-22 / 내용은 제안]
==================================================================
배경: 플레이어의 결정을 Choice 노드 하나로 뭉치지 않고, 에피소드마다 10개 이상 두는 것이 목표 (사용자).
      Decision 은 노드가 아니라 "객체": 흐름도의 어느 노드(Mission · Choice · Event · Interlude)에도 붙을 수 있다.
      Choice 노드 = 메뉴형 Decision 이 모여 있는 화면일 뿐. 층 1 의 모든 결정은 Decision 으로 등록한다.

형식
  D<번호> [상태] <종류> <이름>   (weight: major|std|minor)
    at      : 어느 노드 · 어느 시점에서 발생 (예: C1E1-OP1 진입 시 / 미션 도중 트리거)
    prompt  : 한 줄 (무엇을 묻는가)
    options : 선택지별  ── 비용 / 조건(requires) / 효과(변수 증감) / 파급(consumer)
    consumer: 이 결정의 결과를 "읽는 곳" 이 최소 1개 있어야 한다 (미션 편성 · 적 배치 · 이벤트 · 엔딩 변수 등).
              소비처 없는 결정은 만들지 않는다 (= 숫자만 오르내리는 장식 금지).
    default : 시간 제한 · 무응답 시 기본 선택 (없으면 생략)
    once    : 한 번만 / 반복 가능

종류(kind)
  CHOICE    메뉴형 선택 (미션 사이, Choice 노드)
  APPROACH  미션 진입 방식 (정면 / 우회 / 야간 등) — 시작 배치 · 적 반응이 달라짐
  SELECT    미션 고르기 (Skirmish 4 중 2, 제한이 걸린 선택)
  INMISSION 미션 도중 팝업 (포격 허가, 포로 처리 등)
  ORDER     VIP 명령에 대한 대응 (따름 · 설득 · 타협 · 무시 · 공적 양보 — HOME_DESIGN §7)
  DEPLOY    홈 구간의 편성 · 보충 결정
  REPORT    결과 보고 방식 (공 · 책임을 누구에게 돌리나)

무게(weight) 가이드 (에피소드당 목표)
  major  2~3개   에피소드 · 챕터 분기 · 엔딩 변수에 영향
  std    5~6개   자원 · 호감도 · 다음 미션 편성에 영향
  minor  3~4개   국지 효과 (그 미션 안에서만)
  합계 10 이상. 제작 부담을 줄이려고 minor 는 템플릿화 (§8 기본값 표에 선택지 틀을 등록).

규칙
  - 선택의 비용은 자금 · 보급 · 시간(Skirmish 횟수) · VIP 호감 중 하나 이상 (공짜 최선 금지).
  - 한 결정에 선택지는 2~4개. "아무것도 안 함" 은 명시적 선택지로 둔다.
  - 눈에 보이는 결과와 숨은 결과를 구분한다 (visible: 비용 · 즉시 효과 / hidden: 파급 · 나중에 드러남).
  - 같은 VIP 가 연속 3개 결정에서 계속 불이익을 받지 않게 호감 증감을 에피소드 단위로 점검한다.
