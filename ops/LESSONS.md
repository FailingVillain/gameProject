# LESSONS - 파이프라인 교훈 모음 (2026-10-22 자율 가동에서 추출; 상세 = PIPELINE_LOG.md)

## 발주 전 (지휘자)
1. QUEUE 행은 낡을 수 있다 → 발주 전 MERGE_QUEUE 완료표·main 코드와 대조(T18). 같은 카드의 워크트리·브랜치가 이미 있는지 확인(T16 이중 발주).
2. 작업 종류에 맞는 역할 선택 — 코드 작업을 docs(haiku)에 주지 않는다(T26).
3. 스택 발주 시 선행 카드의 리뷰 blocker 상태·기반 커밋 해시를 프롬프트에 적는다(T09 재스택).
4. 번호(FV/Replay)를 올리는 브랜치는 FV_RESERVATIONS.md 에 먼저 적는다.
5. L 카드는 사전 분할(T19 성공) — 큰 opus 카드는 190~240k 토큰까지 감.
6. 세부 설계가 없는 카드: '기본 꺼짐 스위치 + 초안 수치'를 수용 기준에 미리 적는다(T10). 결정 선택지에는 키 이름·대상을 명시(T06 '×0.75').
7. 측정 목표가 있는 카드는 '목표 미달'을 정직하게 보고하게 하고 wip-ready 로 올리지 않는다(T06·T16·T31c).

## 에이전트 운영
8. 에이전트가 멈춰 보여도 heavy_gate 대기일 수 있다(첫 T16: 5.5시간 후 정상 완료) — 정지 판정 전 게이트·빌드 폴더 확인. 장시간 렌더(T11)는 에이전트 수명과 분리된 잡.
9. 에이전트는 자기 브랜치 밖(main 폴더 ops/QUEUE.md 등)을 건드리지 않게 한다(T10b 위반).
10. 지휘자는 wip-ready 보고를 받을 때마다 main QUEUE 행·FV 표를 동기화한다.
11. 병합 안 하는 정책에서도 리뷰 단계는 유지 — 리뷰 15/15 에서 결함 포착(blocker 1·수용 기준 미달 3 포함).

## 기술
12. 옛 저장소 패치: 처음부터 `git apply --reject --directory=korean-division` (3way 불가).
13. 자료 JSON 은 Load/Validate 에서 null·NaN·범위 검증(T19d·T29b·T10b). 설정 플래그를 바꿀 때는 sim 소비처를 grep 으로 확인(T10).
14. 측정 전용 통계는 FormatVersion 을 올리지 않는다(T19b). 엔티티를 Units 밖에 둘 때는 저장 참조·태그부터 설계(T30b).
15. UI 퍼즈는 작은 버튼을 못 누른다 → 새 버튼은 selftest 로(T19c). `KD_SELFTEST_ONLY` 는 묶음 하나만.
16. 시험이 낡은 것과 코드가 틀린 것을 구분(fix/n12-forest): 약화 금지, 근거 제시.
17. 측정: n=8 판 승률은 표준오차 17%p라 하락 판정 금지 — 의심되면 n>=24 로 재확인(artillery_spotters 5/8 -> 18/24 노이즈).
18. 에이전트 정지 판정(정정 13:1x): 태스크 출력 파일 0바이트·워크트리 무변화만으로는 정지가 아니다 — T16b 원본 에이전트는 85분간 스크래치패드(Temp/claude/.../scratchpad)에 중간 결과를 쓰며 러너 프로세스(PID)를 돌리고 있었다. 정지 판정 전에 ① tasklist 로 러너 프로세스 ② scratchpad 최근 파일 ③ heavy_gate 를 확인하고, 중복 발주는 막을 것(에이전트는 중간 결과를 카드/워크트리에도 적게 지시).
19. 우선순위(사용자 2026-10-22): 기능 먼저, 밸런스 패치·측정은 최후(사용자 결정 시에만). 에이전트 프롬프트에 n=8 동작 확인만, 승률 측정 생략을 명시.
20. 읽기 전용 검토(reviewer·scout)에는 git checkout 을 시키지 않는다 — 검토 에이전트가 checkout 으로 main 을 떠난 사고 (15:1x).
21. 저장 프로필(ObjCodec 대상) 필드를 추가하면 기본값이 꺼져 있어도 FV 를 올린다 — T34a 리뷰 차단 (FV 미상승 → 옛 저장 오독 위험).
22. 힙 증가는 강제 GC 후에 판정한다 (GC.GetTotalMemory(true)) — GC 전 쓰레기로 인한 착시 (T50 계획).
23. 병합 단계마다 snapshot + --snaptest 를 실행한다 — B6~B8 에서 생략해 B9 에서야 actingCache 누락을 발견.
24. 발주 전 관련 워크트리의 미커밋 변경을 git status 로 확인한다 — T38j 중복 발주 (t38e 에 이미 구현).
25. 게이트 대기는 렌더 레인이 풀을 채우면 빌드를 굶긴다 — 카운팅 + RAM 예산(gate 12 · heavyRAM 14GB)으로 해결.
26. 웹 조회는 Gemini 로만 한다 (hub ask -w) — 직접 검색은 사용자 규칙 위반 (제목 검증 중 두 차례 지적).
27. 스프라이트 셀 폭 192px 제한이 엎드려쏴 자세를 잘라 총구가 깨진다 — 자세는 칸 경계(edge_check)까지 확인한다.
