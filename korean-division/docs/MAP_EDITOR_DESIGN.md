작성: 2026-10-22 (spec) · 상태: **제안** (코드 없음) · 보류 해제: 사용자 2026-10-22 · 카드 T33a~T33d
근거 로드맵 (사용자 2026-10-21): "자동 생성 지도를 사용자가 조금 수정 -- 지형 칠하기 · 참호/철조망 · 목표 · 시작 위치 · 저장. 미션별 배치는 사용자가 구술 -> 생성 파라미터." (ROADMAP_LONG 4절)
선행 설계: `game-tools/mission-editor/DESIGN.md` (2026-10-19, **무거운 미션 편집기** -- 병력 · 사건 · 캠페인 포함, 구현 안 함). 이 문서는 그 **부분집합인 지도 전용 가벼운 판**이다. 겹치는 부분 (Core 링크, `ValidateAll`, 왕복 골든) 은 그 설계를 재사용하고 중복하지 않는다.

## 0. 현재 지도 파이프라인 (조사)

- 지도 형식 `MapFile` (`src/Core/MapFile.cs`): `width height base`, `paint[]` (`terrain` + `rect` / `circle` / `tiles`, 순서대로 덮어씀, `"high"`/`"low"` 는 고지 층만), `starts[]`, `sites[]` (점령 시설), `units[]`, `weather/time/schedule`, `factions[]`. **main 에는 `line` 이 없다** -- `rail` 브랜치 (T07, wip-ready, `kd-develop/kd-rail`) 가 `paint[].line=[x0,y0,x1,y1,...]` 와 지형 `rail`(`TerrainType.Rail`) 을 추가한다.
- 미션은 지도를 **이름 참조** (`map` -> `assets/maps/<id>.json`: battle_flat, battle_terrain, battle_city, corners4, flat4, terrain_demo) 또는 **내장 `mapData`** (지도 파일과 같은 객체, 예: c0_02_yalu) 로 가진다. 로더 `MissionDef.Load` -> `WorldMission` -> `MapFile.LoadText`; `FileHash` = 지도 텍스트 SHA256 (스냅샷에 실림, `MapSnapshot.cs`).
- 미션이 지도 위에 얹는 것: `props[]` (손 배치 엄폐 소품 `{type,x,y}`), `propScatter/propDensity/propCell` (결정적 흩뿌리기, `GameMapProps.ScatterProps`), `areas{}` (이름 구역 rect/circle -- 목표 · 사건이 참조), `deployZones[]`, `objectives[]` (`area` 참조), `forces[]` (`at`/`area`/`facing`).
- 현재 지도 제작 수단: 손으로 JSON 작성 + `tools/bn_campaign/gen_scen*.py` 일회성 생성 스크립트. 시각 확인은 게임 `--shot out.png [--shot-frame N] [--sim 초]`, `--map <id>`, `--menu-shot` 뿐. 지도 편집 도구는 없다. 게임에 `--mission-file` / `--mission-validate` 도 없다 (선행 설계가 제안만 함).
- 지형 종류 (main) 11 + 고지 층: Grass Dirt Sand Water Rock Forest Rubble House Wire Trench Crater. 도로 = Dirt 띠, 강 = Water 띠, 다리 = 물 사이 Dirt 띠 (전용 타일은 N52 로드맵).

## 1. 무엇이 "가볍다" 인가 (제안)

| 안 | 내용 | 평가 |
|---|---|---|
| **A. 별도 exe, 지도만** (권장) | `game-tools/map-editor/` 별도 프로젝트 (C# + Raylib, 게임 Core/Render 소스 링크). 한 번에 지도 하나. 미션 JSON 의 `mapData` 와 `props/areas/deployZones` 의 위치만 수정, 나머지는 건드리지 않음 | 2026-10-19 사용자 결정 ("게임 안 기능이 아니라 별도 도구") 과 일치. 게임 코드 수정 최소 |
| B. 게임 안 편집 모드 | `KoreanDivision --map-edit <id>` 로 같은 창에서 편집, 렌더 그대로 (WYSIWYG) | 렌더 재사용은 쉽지만 위 결정과 충돌, Game.cs 핫스팟 (H2~3) 접촉 |
| C. 외부 Python/웹 | 검증 · 타일 규칙 복제 | 드리프트 -- 기각 (선행 설계 2절과 동일) |

"가볍다" 의 정의: **(1) 지도 한 장을 칠한다 (병력 편성 · 사건 · 대사 · 캠페인 연결은 안 함), (2) 새 런타임 형식을 만들지 않는다 -- 출력은 기존 JSON 필드뿐, (3) 단일 화면 + 몇 개 도구 + 저장/다시 불러오기/테스트 실행, (4) 위젯은 버튼 · 숫자 입력 · 목록 정도.** 무거운 미션 편집기 (선행 설계) 는 이 위에 나중에 얹는다.

## 2. 최소 기능 집합 (MVP)

1. **열기**: 지도 파일 (`assets/maps/*.json`), 미션 JSON (`mapData` 내장 / `map` 참조 -> "내장으로 복사"), 자동 생성 결과 (6절).
2. **지형 브러시**: 점 / 선 / 사각 / 원 / 채우기 / 지우개(base), 지형 11종 + 고지 층 토글, 브러시 크기, 우클릭 지우기. 프리셋 스탬프: 도로(Dirt 선), 강(Water 띠), 참호선(Trench), 철조망(Wire), 마을(House 군집 + Rubble).
3. **소품**: `props.json` 종류 팔레트에서 클릭 배치 / 삭제 (미션 `props[]`), `propScatter` 켜기 + `propDensity/propCell` 숫자 (결정적 -- 미리보기는 게임 함수 호출).
4. **건물 / 점령 시설**: `sites[]` (type = capturable 건물 키, owner) 배치. 장식용 독립 건물은 현재 형식에 없고 House 지형 칸으로 표현 -- 질문 4.
5. **시작 지점**: `starts[]` (세력 순서) 드래그. 미션 사용 시 `deployZones` 사각 / 원.
6. **목표 마커**: 미션의 `areas{}` (이름 구역) 를 그리고 `objectives[].area` 가 가리키는 것을 표시. 목표 종류 · 텍스트는 편집하지 않고 보여주기만. 새 구역 이름 입력 + 목록 선택까지.
7. **유닛 배치 (선택)**: 지도 파일 `units[]` (유닛 id + 좌표 + 수) 만. 미션 `forces[]` (중대 편성 · 계급 · 대형) 와 열차는 **범위 밖** -- 질문 5.
8. **저장**: 지도 파일 / 미션 `mapData` 객체로 직렬화 (3절). 임시 파일 작성 후 교체. 저장 직후 `MapFile.LoadText` 로 재적재해 게임과 같은 검증 통과 확인.
9. **테스트 실행**: 저장 후 게임 exe 를 `--map <id>` 또는 `--mission <id> --mission-start` 로 실행. 임시 사본용 `--map-file <path>` / `--mission-file <path>` 는 게임에 작은 플래그 추가 (sim 영향 없음) -- 질문 3.
10. **되돌리기 / 다시**: stroke 단위 가역 레코드 스택.
11. **검사 패널**: 시작 위치 지도 안 + 통행 가능, 시작끼리 최소 거리, 통행 불가 칸에 갇힌 시작 / 목표 (도달성 -- 게임 길찾기 호출), 소품 · 시설 겹침.

## 3. 결정론 / 데이터 원칙

- **편집기 출력 = 데이터 JSON 뿐**. 시뮬 코드, 스냅샷 `FormatVersion`, 리플레이 형식, 체크섬 규칙은 건드리지 않는다. 편집된 지도는 게임이 일반 지도와 똑같이 로드하고 `FileHash` 로 식별한다.
- 직렬화는 **정규화**: 키 순서 고정, paint op 순서 보존 (뒤가 앞을 덮음), 정수, 한국어 그대로, 들여쓰기 고정. 같은 문서 -> 같은 바이트 (골든 해시 비교).
- 칠하기 의미 보존: 편집기는 paint 목록을 **게임과 같은 코드** (`MapFile.Build`) 로 래스터해 보여준다 (복제 금지). 저장은 (a) 도형 op 는 도형 그대로, (b) 자유 칠하기 stroke 는 `tiles`, (c) 생성 지도에서 가져온 변경 칸은 `tiles` 로 추가. 크기 상한 경고.
- 편집기 자체에 난수 없음. `propScatter` 미리보기는 `GameMap.ScatterProps` 호출 (시드 = 미션 seed).
- 알 수 없는 필드 보존: 미션 JSON 은 `mapData` / `props` / `areas` / `deployZones` 서브트리만 교체하는 JsonElement 단위 치환. `//` 주석은 파서가 제거하므로 질문 2.

## 5. 시험 / 스크린샷 접근

- **헤드리스 단위 (T33a)**: 문서 모델 연산 -> 직렬화 -> `MapFile.LoadText` -> 타일 격자 비교. (1) `assets/maps/*.json` 전부 열기 -> 저장 -> 로드한 타일 · 고지 · 시작 · 시설이 원본과 동일, (2) 연산 후 undo = 원본 해시, (3) 같은 연산열 -> 같은 출력 바이트, (4) 미션 `mapData` 치환 후 `MissionDef.Load` 통과 + 나머지 필드 불변.
- **UI 시험 (T33b)**: 편집기에 `--script <file>` (입력 이벤트 목록: `tool brush`, `drag x0 y0 x1 y1`, `key ctrl+z`) 와 `--shot out.png` -- 게임 `--shot` / `--menu-shot` 과 같은 방식 (고정 1/60 프레임, 입력 대체). 스크립트 재생 결과 파일 해시 + 스크린샷 contact sheet 를 사용자가 눈으로 검수.
- **통합**: 편집한 지도를 `--map <id> --shot` 으로 게임에서 렌더해 편집기 화면과 같은 지형인지 비교 시트 한 장.
- 가벼운 작업 (Wlight). 게임 `--selftest` 는 카드가 게임 코드를 건드릴 때만.

## 6. 자동 생성 지도 가져오기

로드맵 취지 = "자동 생성 -> 사용자가 조금 수정". 현재 생성 파라미터 (강 · 도시 · 철도 · 고지 · 참호선) 는 아직 없고 사용자가 미션별 구술 예정. 편집기는 생성 지도를 **결과 격자로만** 가져온다 (생성기로 `GameMap` 을 만들고 base 와 다른 칸을 `tiles` op 로 기록). 사용자가 구술한 배치가 생성 파라미터가 되면 편집은 그 위의 미세 수정으로 남는다 (질문 6).

## 8. 위험

1. Raylib 위젯 직접 작성 -> 버튼 / 숫자 / 목록으로 제한 (T33b).
2. Core 소스 링크가 게임 csproj 와 충돌 -> 링크 전용 csproj 만 추가, 게임 csproj 불변.
3. 큰 지도의 `tiles` 직렬화가 거대 -> 도형 우선 + 크기 경고.
4. 왕복 손실 (주석 · 키 순서) -> 서브트리 치환 + 원본 텍스트 보존, 질문 2.
5. `rail` 병합 전 -> 철도 도구는 T33d 로 분리해 막힘 방지.
