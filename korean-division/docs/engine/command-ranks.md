# Engine notes - command-ranks (squads · NCOs · command ranks · tactical-frame behavior · officer style) [split from ENGINE_NOTES.md 2026-10-23, body verbatim] (엔진 노트 - command-ranks (분대·부사관·지휘 계급·전술 틀 행동·장교 성향))

### Squads · NCOs · ranks · vacancy check · chain-of-command delay (분대 · 부사관 · 계급 · 빈자리 점검 · 지휘 계통 지연) (2026-10-19, ROADMAP §2-7 "④ 구현", `src/Core/Squads.cs` · `CommandDelay.cs` · `Ranks.cs`, test `Tests/SquadSelfTest.cs`)
- **Squad** `Squad` (Id · Number (within company) · Company · Members in Id order): `Company.Squads` (in number order), back-reference `Unit.Squad`. Every member except the officer belongs to exactly one squad. `BuildSquads` = only at organization · splitting (when there is one squad or fewer) - cut evenly in order of the widely spread axis coordinate. `LeaveCompany` → `LeaveSquad` → empty squads removed / below `squadMergeBelow` → `MergeDepleted` (merge into the nearest-center-of-mass squad where the sum is <= squadMax → otherwise each soldier to the nearest squad with a vacancy → otherwise leave as is). Death order = reverse iteration of RemoveDead (deterministic).
- **Squad leader** `Squad.Leader` = highest `Rank` (ties by Id order) - a derived value, not saved. `Unit.IsNco` = enlisted rank >= `ncoRank`. `World.NcoLeads(u)` = the squad leader is an NCO and within the leader's `ncoRadius` (including the leader himself). Applied in `DecaySuppression` · `MaybeHesitate` only when `NearOfficer` is false (no stacking).
- **Rank**: `combat.rankKills` 8 entries → `RankOf` 0..8, `killsCap` 128 (`CountKill`). `Unit.OfficerRank` = officer 0 (no state). Names `RankNames` (`assets/data/ranks.json`, read by `Defs.Load` from the same folder, display only, font atlas via `Defs.AllText`). HUD `Hud.RankName(u)` = map `factions[].en` key.
- **Vacancy check** `StepGapChecks` (Step: after StepAnchors, before unit update): `Company.Holes` = number of `LeaveCompany` since the last formation (`StartCompanyMove` sets it to 0) (when Facing exists). `(Tick + companyId×97) % (gapCheckSec/dt) == 0` · Holes > 0 · no Anchor · `CompanyOfficer` (company officer → a same-faction officer in command range) → `RefillCompany`: center of mass · Facing · `OrgLayout.CompanySlots(Form, n)` + `Formations.Match`, only soldiers who are Idle · in no group · not charging · reaction delay 0 and deviating from their slot by more than `gapMoveMin` → a new arrived-state (`Arrived = true`) `CompanyAnchor` + AttackMove (target kept). In combat (a member has a target or fired in the last 3 s) each officer rolls `Roll(Id, 0x5357) < swordWaveChance` → `SwordWaveTick = Tick` → `UnitArt.LodFrame` plays sword_wave once (not while charging).
- **Chain-of-command delay** `Acknowledge` → `ReactDelay = ReactDelayFor + ChainDelayTicks`. `ChainTierOf`: officer · (if infantryOnly) non-infantry = None, a same-faction officer within command range = Officer, no squad · alone = Isolated, a living NCO in the squad = Nco, otherwise = Acting. Delay = tier range × `Roll(Id, 0x43484E)` (hash including tick), × `retreatMul` if Order == Move (not charging). The officer list `cmdOfficers` is gathered anew from Units for each command bundle (the `officers` of RebuildHash is the previous tick's value at command time and could disagree with a loaded world - a working value, not saved). Tests from before the delay was introduced (Combat3/4 · Aim · Nav · Org) turn it off with `TestDefs.NoCommandDelay()`.
- **Partial selection**: `StartCompanyOrders` / `PreviewSlots` - a command that selects only some of the company members is an old-style formation group (temporary bundle) without a flag, membership unchanged.
- **Selection UI** (`Game.cs`): `FinishSelectionCore(alt)` Alt+drag = squad expansion, Shift = company expansion, double-click = `CycleEchelon` (selection is entire squad → company → battalion → squad), squad chip `Hud.SquadChipAt` → `SelectSquad`.
- **Save**: ORG_ = nextSquadId + per company Holes · squads (Id Number members) - on load validated that members belong to that company · no duplicates. SwordWaveTick = later in CMB2 (WriteCombat3). Checksums `HashOrganisation` · `HashCombat3`. FormatVersion 11.
### Command ranks · temporary promotion · succession · officer experience (지휘 계급 · 임시 진급 · 승계 · 장교 경험치) (N3, 2026-10-19, `src/Core/CommandRanks.cs`, test `Tests/CommandSelfTest.cs` = `KD_SELFTEST_ONLY=command`)
- **Rank number** = ranks.json `officer` index (0 undecided '장교' · 1 소위 · 2 중위 · 3 대위 · 4 소령 · 5 중령 · 6 대령). `Unit.OfficerBase` (formal, byte) + `Unit.TempRank` (temporary promotion in combat, <= `officers.maxTempPromotion` 3) → `Unit.OfficerRank` = sum (capped at maxRank). Enlisted ranks · promotion (campaign only) unchanged.
- **Post assignment** (`AssignCompanyRanks`, inside ExecFormCompany): only officers with an undecided (0) rank - the company's first officer 대위 (skipped if there is already a 대위 or higher) · second 중위 · the rest 소위 (in Id order). An officer who already has a rank keeps it (reorganization). Battalion commander = highest seniority in the battalion (rank → experience → Id), post rank = 중령 if the battalion has `battalionSeniorCompanies` 3 or more companies, otherwise 소령. **Deployment phase** (`SpawnRanks.Auto` - `FinishStartForce` standard starting force · mission `SpawnForce`) formally promotes the battalion commander (`ConfirmSpawnPosts`) · no handover. For a force where the mission specifies even one `officerRanks` (deployment order, both companies and loose bundles), `SpawnRanks.Explicit` = the specified ranks as is (no automatic promotion · no temporary promotion). `officerXp` = starting experience. **In-combat organization** (player · tactical AI `FormCompany`) has **no promotion** - only gives command to the officer with the highest command priority (`Senior`: experience → rank → Id) (changed 2026-10-19). Temporary promotion (`TempPromote`) happens **only on commander death · departure succession**.
- **Assistant battalion commander** (부대대장) (`AssistantOf(Battalion)`, derived · not saved, `OfficerPost.Assistant`): in a battalion with `battalionSeniorCompanies` (3) or more companies, the officer next in priority after the battalion commander. Deployment-phase Auto formally promotes to 소령 (`battalionRank`) (`ConfirmSpawnPosts`), in-combat organization has no promotion. A 대령 (regiment commander) is only by mission specification.
- **Commander**: `Company.Commander` · `Battalion.Commander` (saved · checksummed). Company commander = highest seniority among company officers, the battalion commander also serves as company commander only when there is no other officer in the company (`ValidCompanyCommander`). Decision times: organization · splitting · battalion attachment · departure (`AttachCompany` · `DetachCompany` · `ExecSplit` · `LeaveCompany` → `OnCommandMemberLeft`) + the `StepCommand` safety net (every tick, after StepAnchors · before StepGapChecks).
- **Succession**: when the commander is lost (death · departure) the next-ranked officer immediately becomes `Commander` and is temporarily promoted to the post rank, with no command ability during `HandoverUntil = now + handoverSec (5 s) × experience multiplier`. With no officer, `Commander = null`, and after `ncoHandoverSec` (8 s) an NCO acts. On the first decision (a company that had no commander) it is immediate.
- **Ability level** (`CommandLevelOf(Company)`, public API for N4): during handover None · officer Officer · acting NCO (the highest rank among formal NCO squad leaders, `ActingNco`) Nco · nobody None. `CommanderOf(Company)` = officer ?? acting NCO. `TacticAllowed(level, tactic)`: officer all · NCO = no frame · fire-and-maneuver only · None = no frame only (for now only exposed - the code that blocks frame switching is N4). `PostOf(Unit)` (post for display).
- **Connection to existing command**: `CompanyOfficer` (the vacancy-check · march-fire judging officer) = the company commander (null during handover - deputizing for another company's officer's command range also only after handover ends). Chain-of-command delay (`ChainDelayTicks`) × `ChainDelayMul` (experience) for company members commanded by an officer. March-fire judgment interval · vacancy-check interval = `DecideInterval(c, iv)` (experience). The officer command-range effects (`NearOfficer` suppression decay · fire interval) stay as physical distance.
- **Experience** `Unit.OfficerXp` (int, cap xpMax): every 1 second the company is in combat (a member has a target or fired within `combatWindowSec`) that company's officer gets +xpCombatPerSec (`StepCommand`, spread by company Id) · for every enemy unit killed (`CountKill` → `CreditKillXp`) the shooter company's officer gets +xpPerKill · the battalion commander (if a different company) +xpPerKillBattalion (mission-objective-completion experience was removed). Level = number of `xpLevels` thresholds passed (`XpLevel`). Per level judgment interval ×(1 − xpDecidePerLevel) · command delay ×(1 − xpDelayPerLevel) · handover time ×(1 − xpHandoverPerLevel), floor ×0.5.
- **Save**: FormatVersion 23 - CMB2 per unit `OfficerBase` · `TempRank` (byte) · `OfficerXp` (int), end of ORG_ (`WriteCommandState`, after the tactical frame) commander Id per battalion · company (0 = none) · `HandoverUntil`. Checksums `HashCombat3` · `HashCommandState`. Replay format unchanged (no command added).
- **Result file** (`MissionResults.UnitLine`): officers only `officerRank` (formal) · `tempRank` · `xp` · `post` (battalion · company · staff). Temporarily promoted officers also appear in `promotions`.
- **HUD**: officer info rank line = "중령 (임시 · 대위) · 대대장 · 경험치 120 (Lv1)", end of the company card detail line "지휘: 대위 (인계 중)" / "하사 (부사관 대리)" / "지휘관 없음". Strings `S.XpLabel` · `S.TempRankTag` · `S.Post*` · `S.CommanderTag` · `S.HandoverTag` · `S.ActingNcoTag` · `S.NoCommander`.
- **Promotion cap = 중령** (user decision 2026-10-19, branch `rankui`): balance.json `officers.maxPromotionRank` 5. Neither temporary promotion (`TempPromote`) nor formal promotion of the battalion commander / assistant (`ConfirmSpawnPosts`) can go above this. A 대령 (regiment commander) placed by a mission is left as is - the cap applies only to promotion (the `OfficerRank` clamp stays at `maxRank` 6). With default values the post rank is already <= 중령 so sim results are unchanged (golden `5ddc12819138e852 170ca08c8d3ef2c5` as is, no state · save added). Test `CommandSelfTest.TestPromotionCap`. Per-faction rank names stay `RankNames` (ranks.json faction key → Korean default) - when a new document arrives, only add a table there.

- **March-fire trigger distance** (행진 사격 발동 거리) (2026-10-19): `MarchRadius` = min(weapon range, short-range sight × `marchSightFrac`), `marchSightFrac` 0.5 → **0.7** (0.7 times the effective range). Vehicles' individual march fire uses the same key.

- **LMG burst fire** (경기관총 점사) (`src/Core/Bursts.cs`, FormatVersion 24): the state is the single `Unit.BurstLeft` (CMB2 saved · HashCombat3 · Audit [SnapExt]). The pause is added to `Cooldown` at the last shot (no separate timer). Call sites = WorldCombat.Engage fire (BurstAfterShot) · Combat4 march fire. Target loss = BurstTargetLost in UpdateUnitCore, new target = BurstLeft=0 when AimTarget changes. Render · sound are per shot (LastShotTick, SfxDirector lmg) so the burst is heard as is and the pause shows the aiming posture.

### Tactical frame stage 2 - role behavior · commander switching · heavy-weapon pacing (전술 틀 2단계 — 역할 행동 · 지휘관 전환 · 중화기 보폭) (N4, 2026-10-19, `src/Core/TacticDrill.cs` · `HeavyPacing.cs`, data `tactics.json` act · behaviour, test `Tests/TacticDrillSelfTest.cs` = `KD_SELFTEST_ONLY=drill`)
- **Executed frame** `Company.ActiveTactic` = `Company.Tactic` (the frame chosen by command, remembered) filtered by command ability (`GateTactic`: officer = all, acting NCO = fire-and-maneuver, no command = no frame). Judgment = `StepTactics` (after StepFormationTriggers · before StepAnchors) per company at `DecideInterval(c, behaviour.decideTicks 30)` tick intervals (shortened by experience), **judgment · switching pauses during handover (`InHandover`)** (`Stats.DrillPaused`). The command `cotactic` for a frame that is not allowed gives a rejection notice + remembers only. Layout (`CompanyLayout.Build`) · behavior use ActiveTactic. HUD detail line "전술 틀 (지휘 제한: 실행 틀)".
- **Phase** `Company.Drill` (`DrillState`): Idle → contact (a member has a target · fired within contactSec) + enemy within range × approachFrac (or company standing) → Engage (defense in depth = Defend if stopped) → contact breaks for disengageSec (10 s) → Idle + re-align to the company formation (RefillCompany). External company orders: ordinary movement (quick step · retreat) = behavior reset + no behavior until arrival (Passive), attack-move = phase kept · only an in-progress bound/maneuver ends. No vacancy check during frame behavior.
- **Role behavior** (`act`): hold = gunner (trench · target kept, machine gun auto-emplaces) · bound = fire group squads bound in turn (one squad boundLength 6 tiles ordinary movement, the rest gunner, relieve after arrival · boundMaxSec, up to range × rifleStopFrac, stops if company suppression >= boundSuppression) · manoeuvre = the maneuver group quick-steps via a waypoint (keeping the current enemy distance toward the frame angle) → frame-angle position (angle relative to the enemy, standoff × range), fires from place, redoes if the enemy moves · follow = follows by attack-move · support = gunner + priority targets of threats (tank · machine gun · officer) (`FindTarget(threat)`) · command = commandBack behind the fire group (when there is no bound · maneuver, per the company order - the officer stays with the company) · trench = occupies an empty trench spot within trenchSeek · reserve = reserve gunner, if enemies around the fire group >= counterMin or an enemy is closer to the reserve than the front, a bayonet counterattack → back to place.
- **Wait for fire superiority** (`wait` default true): bound · flank requires the average suppression of visible enemies around the company (range + superiorityRadius) >= superioritySupp (0.55 → **0.20**, N17 2026-10-19) (before that, the company order - the player's or tactical AI's approach · gunner - stands as is). If the firefight exceeds patienceSec (60 → **90 s**, N17), only a bound is allowed, and only when the bound target is better in cover than the current one by boundCoverGain or more. A flank requires target · waypoint cover >= manoeuvreCover (0.5) or enemy suppression >= manoeuvreOpenSupp (0.8). The numerical-superiority rule (superiorityFew) defaults to 0 = off (the first contact in fog shows only part of the enemy, causing overestimation). Assault-frame maneuver group = wait false.
- **Assault** (`TryDrillCharge`, maneuver group · follow · reserve): immediately if the nearest enemy is within chargeRange (6, assault frame 9), otherwise within chargeMaxDist (12) + enemies around it within chargeStatsRadius have suppression >= chargeSuppression or assault strength >= chargeOdds × enemies + no machine gun firing within chargeMgRadius + our suppression < 0.5. **Lift fire**: if the maneuver group is within liftDist (8) of the enemy, during `Drill.LiftUntil` the fire group · support · fire group do not target enemies within liftRadius (5) of LiftPos (`TryAcquire` → `FindTarget(avoid)`) and also drop targets already acquired.
- **Artillery formation**: on contact it deploys with `templates.artillery.deployTactic` (fire-and-maneuver) (`forcePlacement`), and if command ability does not allow it, a deployForm line without a frame.
- **No re-layout during contact** (`CompanyLayout.InContact` = phase ≠ Idle or a member has a target): re-aligning to role-group positions while firing made them walk instead of shoot (measured). Behavior works by role, so it runs even without layout.
- **Stage-1 overlap fix**: role groups in the same row (depth difference <= 0.5) share the front width by strength ratio (`Wrap` - overflow folds squad blocks backward), and when overlapping, the side that moves less (sideways, or backward if over ¼ of the width) yields (`Separate`). Role-group center-of-mass error for a 100-man company <= 0.10 × width (stage-1 fire group 19 tiles ≈ 0.36). `flanks` = squads in two left/right lumps (defense-in-depth machine guns on both flanks).
- **Heavy-weapon pacing** (user rule 2026-10-19, `HeavyPacing.cs`, `UnitDef.Heavy` = key heavy_* or branch gun): every tick (before unit update) company = flag formation front (`FinalDir`, also while walking to slots after arrival) · in engagement phase toward the enemy, infantry front = maximum projection in that direction (a heavy-weapon-only company uses the battalion infantry), mixed movement bundle outside a company = infantry center of mass → target. If a heavy weapon would advance that tick beyond front + `HeavyLeadTol` (1 tile) the movement is reverted (`Stats.HeavyHeld`). Sideways · backward movement (re-emplacing sideways while infantry hold) is allowed. Layout: `CompanyLayout.Match` swaps front-slot heavy weapons ↔ rear-slot infantry within a bundle (`HeavyBack`), and the frame's fire group · support are level with or behind the fire-group row. Tactical AI: fire-base position = at or behind the friendly infantry front, howitzers = 8 tiles behind the front (`BehindInfantry`).
- **Tactical AI**: profile `tactics.templates` **default true** (user decision). Defense task = defense in depth, attack = fire-and-maneuver after members acquire targets (switching to the frame layout while approaching stopped the flag through re-alignment, and only the fire base moved ahead). The AI stops detailed company orders only during a bound · maneuver-group flank · assault (or throughout a defense-in-depth phase), and defense-in-depth-frame companies send out no outposts. Measurement profiles `tactical:templates` · `tactical:notemplates`. `--balance sim` prints the cumulative "frame behavior" (틀 행동).
- **Save**: FormatVersion 26 (merge order: after burst 24 · cavalry cooldown 25) - ORG_ tactical-frame section per company ActiveTactic + DrillState (phase · Passive · tick · enemy position · original position · bound squad · maneuver-group state · target · waypoint · lift). Checksum `HashFormationState` (only companies that use frame · behavior state). The heavy-pacing reference · judgment buffers are recomputed every tick (not saved). `Defs.Hash` = balance.json + formations.json + tactics.json (length header + content, `Defs.HashOf`).
- **Demo console**: `famove dx dy [width]` (attack-move - frame behavior), `fcam [dx dy]` (camera = center of mass of the chosen company). Example: `--battle "infantry:36,heavy_machinegunner:8,officer:1" --vs "infantry:12" --ai none --nofog --exec "zoom 0.5" --exec "org 45 1" --exec "after 3 ftac flank_left" --exec "after 6 famove 55 0" --exec "after 1790 fcam 10 -4" --sim 30 --shot x.png --shot-frame 5`.

### ai412 - assault clearance (decision 4) · battalion roles (decision 12) · default NCO organization (ai412 — 돌격 허가 (결정 4) · 대대 역할 (결정 12) · 부사관 기본 편성) (2026-10-19 user approval, branch `ai412`, test `Tests/Ai412SelfTest.cs` = `KD_SELFTEST_ONLY=ai412`)
- **Assault clearance** (`World.AssaultClearance`, TacticDrill.cs - read-only, visible enemies only): the engine maneuver-group charge (`TryDrillCharge`, both nearness · suppression) and the tactical AI attack-company charge (`TryAssault(attack: true)`) must get clearance again after passing the old conditions. Clearance = strength ratio (assault-capable men >= visible enemies within the target's `chargeStatsRadius` × `assaultMinOdds`) **and** (fire-superiority signal = average suppression of visible enemies around the company within range + `superiorityRadius` >= `superioritySupp` **or** cover confirmation `HasOverwatch` = `overwatchMin` or more friendlies outside the assault party (excluding officers · charging units) fired within `overwatchSec` seconds and the target is within `overwatchRadius` tiles of the assault target). Otherwise only once `assaultFallbackSec` has passed since the engagement began (frame phase `Drill.PhaseTick`, for no frame the tick the AI engagement state was entered) (reserve timer). Data tactics.json `behaviour`: `assaultGate` true · `assaultMinOdds` 1.0 · `overwatchSec` 4 · `overwatchRadius` 8 · `overwatchMin` 3 · `assaultFallbackSec` 150. **Unchanged**: officer auto-charge · march-fire 3-tile auto-charge · melee auto-charge · defensive counterattack (defense-in-depth reserve `DrillReserve`, AI main resistance line · counterattack reserve). Measurement counters `Stats.AssaultSignal/Overwatch/Fallback/Blocked` (not state), the `[돌격허가]` line of `--tactics-obs`.
- **Battalion roles** (`TacticalAi.AssignAttackRoles` · `CombatBattalion`): a battalion whose total living strength of its rifle companies (TacKind.Line) < tactics.json `battalionRoles.minStrength` (40) (1-man detachments · specialist branches only) does not become fire base · maneuver and has no designation (Line). If there is only one combat battalion, that battalion is `Split` (at company level fire base 1 · the rest maneuver, defense-in-depth reserve company rule as is). The new-battalion reassignment check is also for combat battalions only.
- **Default NCO organization** (`World.AssignSquadLeaders`, WorldMission.cs): when mission forces are spawned, each infantry squad's leader (`Squad.Leader` = highest rank · lower Id on ties) gets rank `squadLeaderRank` (balance.json `combat.squadLeaderRank` 5 = 하사, 0 = off). Overridden by mission force · company `squadLeaderRank`, a company with a force `rank` set does not use the default rule. Only `StartKills` (already saved · checksummed) changes - no state added (FormatVersion 26 as is). The NCO effects (`ncoHesitateMul` 0.5 · `ncoDecayMul` 1.5) and N3 acting NCO (keeps the fire-and-maneuver frame when all officers are wiped out) are now on by default → balance change (TACTICS_OBS '9th round').
- Other: moved `stackalloc` in `TacticalAi.Organise` out of the loop (CA2014, same behavior). `--tactics-obs` variants `NoGate` · `NoNco` (isolation tests).

### cavcmd - cavalry officers · cavalry NCO deputies (cavcmd — 기병 장교 · 기병 부사관 대리) (2026-10-19 user decision, branch `cavcmd`, test `Tests/CavCmdSelfTest.cs` = `KD_SELFTEST_ONLY=cavcmd`)
- **Cavalry officer** `officer_cavalry` (balance.json): officer (`commandRadius` 8 → `IsOfficer`, hp 200, pistol · sabre, not suppressed, spotter) + cavalry movement (`mounted`, speed 4.8, charge ×1.8, stamina ×3, radius 0.45, sight 35). No separate branch in code - N3 ranks · posts · succession · temporary promotion · experience · command range (`NearOfficer`) and the cavalry rules (charge impact · charge only · cavalry pursuit · no trenching · no quick step) both apply as is. Faction art = theme variant `unit.officer_cavalry@fengtian` (one common unit).
- **Missions**: in cavalry companies (ai_bn_meeting · ai_bn_assault · ai_kr_vs_ft_1000 both sides, including the `tools/tobs_scen/*` measurement copies) `officer` / `officer_fengtian` 1 → `officer_cavalry` 1. Side effect: since flag movement speed follows the slowest member, **the cavalry company being tied to the infantry officer (3.2) speed is released** (cavalry 4.8).
- **Cavalry squad NCO** (decision 2): `AssignSquadLeaders` originally covered all category `infantry` squad leaders (including cavalry) - the condition is now written as `Def.IsInfantry` and cavalry is stated explicitly. The cavalry squad (max 12 riders) leader = `squadLeaderRank` (하사), mission `squadLeaderRank` override as is. Officer lost → `ncoHandoverSec` 8 s → `ActingNco` (N3). The 9th round 'no command 637 (C)' was not due to cavalry - the command-ability sample of `--tactics-obs` counted only rifle (Line) companies (cavalry companies have the new `[기병지휘]` line).
- **Tactical AI cavalry charge = officer stays behind** (`TacticalAi.CavalryCharge`, tactics.json `cavalry.officerBack` 10, 0 = charge together): in the flank-route arrival charge · planned charge only the riders `Charge`, the officer `Move`s to officerBack tiles in front of the target (opposite the charge direction) (the "command party" principle of the rifle company frame). When charging together the cavalry officer died in the first charge and no-command cases grew (TACTICS_OBS 13th round CAV1). If the enemy is close the officer auto-charge rule stays, player orders stay. The old cavalry AI (`legacy`) is unchanged. The rider count in `PickCavalryPlan` excludes the officer (same accounting as the old infantry officer → minRiders · strength ratio unchanged). Counter `Stats.CavOfficerHeldBack` (end of the `[기병AI]` line 'officer follows behind' (장교 뒤 따라감)).
- **Save**: no state added (FormatVersion as is) - only unit definitions · missions · tactics.json values. Golden updated due to the Defs.Hash change.
- Art: game-tools `units/cavalry-officer.json` (+ `-fengtian`), `bases/cavalry.py` one-handed pistol pose (`tune/poses.json cavalry.pistol`). ART_SPEC 'cavalry officer' (기병 장교).
### Per-faction rank table (세력별 계급 표) (ranks branch, 2026-10-19, source `docs/RANKS_BY_FACTION.txt`, `src/Core/Ranks.cs`, `assets/data/ranks.json`)
