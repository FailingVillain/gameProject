# Engine notes - org-formation-movement (organization · formation · collision · contact · closing ranks · pursuit/retreat) (엔진 노트 - org-formation-movement (편제·대형·충돌·접적·대열 정비·추격/후퇴)) [split from ENGINE_NOTES.md 2026-10-23, body verbatim]

### Unit organization and flag formation (부대 편제 · 깃발 대형) (2026-10-18, ROADMAP §2-4b unit organization stage 2, `src/Core/Organisation.cs` · `OrgFormation.cs`, test `Tests/OrgSelfTest.cs`)
- **Data**: `Company` (≤100, a unit belongs to only one company - `Unit.Company`, number = smallest free number within the faction, `Form` = company formation, `InitialStrength`, `Facing` = last arrival direction), `Battalion` (≤10 companies, number 1~9 / 0 = unnumbered, `Form` = `BatForm` Line · Column · Echelon · TwoFrontReserve). On death · faction transfer `LeaveCompany`, empty companies · battalions are removed immediately. No automatic reorganization · vacancy filling.
- **8 commands** (`FormCompanyCommand(Units, BattalionNumber)` - Alt+number: join the battalion with that number, create if none · Disband · Split (the front half by Id stays) · FormBattalion (automatic number) · SetBattalionNumber (swap) · MoveCompany (0 = remove, rejected if 10) · SetCompanyForm · SetBattalionForm). `FormSpec.Width` added (right-click drag width, 0 in old replays).
- **Flag movement**: `ExecGroupOrder` -> `StartCompanyOrders` detaches company membership and makes a `CompanyAnchor` per company (virtual unit `Flag`, Id = 2^29 + company Id, outside World.Units). Direction = drag Dir -> (if all companies have the same Facing + target within 20 tiles) that direction -> center of mass->target snapped to 8 directions. `OrgLayout.Plan` = company block slots (line 2 ranks · column 4 ranks · square · spread · wedge, with a specified width columns = width/spacing+1) + battalion placement (2-tile spacing, current left-right order preserved). `StepAnchors` (before UpdateUnit): members lagging more than 2.5 tiles behind their slot > 1/3 -> stop, more than 1.2 tiles > 10% -> half, flag speed = slowest member × 0.9, after waiting over 10 s it sets off at half speed, rotation of the direction of travel is limited in angular speed to fit the half width. Members (`FollowAnchor`): steering = rotated slot, path goal = company goal (same path cache as the flag), after arrival `Goal + FinalOff`.
- **Narrow road** (revised in bunchfix 2026-10-19): every 10 ticks the flag's left-right width line (now · 3 tiles ahead · 8 tiles ahead) is sampled at 1-tile intervals (`NarrowBlockedFrac`, tiles where the flag cannot stand · off-map = blocked), if any is blocked by `narrowBlockFrac` 25% or more -> 2-rank column, and when all three stay below that for `narrowClearTicks` 120 ticks in a row -> original formation (old: column if even one tile is blocked · 60 ticks). Column soldiers line up on the flag's trail (`Trail`, 0.5-tile spacing) and the flag waits for only the leading 3 rows (if more than 1/4 of the tail lags, half speed). **If the trail is shorter than the column** (`UpdateColumnRows`), rows are placed at the point extended from the last trail point opposite to the last tangent by (rows × spacing − distance walked) (checked with `SlotOk` every 0.5 tile, stopping before blocked tiles · off-map). Rows that could not be reached (from `RowReach`, working value · not saved) go from the last reachable point to the outer columns on both sides of the column tail (±1.5 · 2.5 · 3.5 spacing, forward by spacing, offset by half a spacing), a different place per column slot sequence number (the opposite side if blocked -> `ShiftSlot`). Old: all rear rows gathered at the single oldest trail point, clumping · rubbing (docs/legacy/BUNCHING_DIAG_2026-10-19.md). Measurement tool `--bunch <mission> --seed N --seconds S --out f.csv [--dump p.csv --dump-at sec,..]` (src/Tests/BunchProbe.cs, read-only), test `KD_SELFTEST_ONLY=bunchfix`.
- **Save**: section `ORG_` (after CMDX) - the buffer is after WriteLinks · before WriteGroups (flag group · path table numbers). The flag saves only pathfinding state. `FormatVersion` 4 -> 5. Checksum `HashOrganisation`. `Formations.Build` also snaps to 8 directions if there is no direction -> detcheck golden updated.
- **Known limits**: scouting · charging use the old way without a flag. The default line is 2 ranks, so 100 units = 47 tiles wide - with many obstacles, column <-> line switching · realignment make it slower than the old way (zigzag wall 100 units: flag ≈180 s vs old 82 s). If a slot is a wall, soldiers stand scattered by soldier-Id hash around the nearest tile where they can stand (`ShiftSlot`) (`BlockedSlotFallback`, spacing × 0.5 grid 15 tiles - before bunchfix: a single flag point) and realign after passing.
### Collision · formation redesign · company march fire (충돌 · 대형 재설계 · 중대 행진 사격) (2026-10-18, branch `collision`, analysis `docs/legacy/COLLISION_ANALYSIS.md`, measurement `--collide`, test `KD_SELFTEST_ONLY=collision`)
- **Overlap resolution** (`World.Separate` · `SeparatePair`): the spatial-hash · tile-order pair iteration is unchanged, pushes are **accumulated into `sepDX/DY` then applied once** (Jacobi - independent of processing order · symmetric). With 3 or more contacts, sum × `SepRelax` 1.5 / √contact count. Ratio `SepStiff` 0.8 (deep overlap · hostile also 0.8), **pairs walking together in the same slot formation** (flag 128 = formation Plan or company flag group, same group · both moving) = 0.5 : 0.5 · ratio 0.5 · margin `SepSlopForm` 0.06 (other margin 0.02). Allied pairs where both are fixed (holding · firing posture, excluding deployed · in a trench = flag 64) = 0.15 : 0.15 stepping aside based on body radius (not the city's double radius) (so they do not harden overlapped). Between trench spots (32) · autonomous scouts (16) still no pushing.
- **Direction**: `MoveToward(..., face)` - within `FaceSlotDist` 0.8 of the slot the body faces the formation direction (flag Heading · arrival FinalDir · formation Plan.Dir), the last 0.25 tile of a move without formation does not turn the body (TurnRate towed guns · during sidestepping as before). The stall sidestep (`NudgeDir`) is not done within 1.5 tiles of the steering point (small units).
- **Flag**: direct-line check distance `FlagDirectRange` 1000 (flat ground = straight line, multiple companies do not gather at the zone path entrance), group movement also `GroupDirectRange` 60 (chase 30 unchanged). Speed multiplier `CompanyAnchor.SpeedMul` (saved) follows the target value (0 · 0.5 · 1) with an acceleration limit (stopping 2/s · starting 1/s). If more than a quarter of members are engaged (aiming · charging), the whole column stops (no waiting cap). A soldier walking attached to a slot goes exactly to that tick's slot position (prevents walk <-> stand flicker). A march slot off the map = to the edge (instead of a single flag point). Mission start placement (`LayoutForce` -> `FitDeployInMap`): if the force formation goes beyond 1.5 tiles (`DeployEdgeMargin`) from the map edge, the formation is moved inward, and if wider than the map, the company block center spacing on that axis is reduced (bunchfix - old: off-map soldiers crowded to the edge tiles, so the edge company became one lump within 5 s of start).
- **Continued walking** (`StartCompanyMove`): when a company on the march (before arrival · not a column) receives a new command with cos > 0.7 to the direction of travel, it inherits the flag position · direction · speed, slots are reassigned based on the current slot positions, soldiers who were walking under the same command have reaction delay 0 · keep their attack-move target.
- **Attack-move formation discipline**: company flag members search for targets only within engagement distance (direct-fire range × engageRangeFrac, indirect range), no chasing (`chase: false`) - they fire standing and the column stops with the flag. Charging chases as before.
- **Large group without formation**: all members are registered at command time (`RegisterBig` - previously registered only on ticks during reaction delay -> with few registered the large group switched off and everyone went to a single goal point), compression ratio = as much as will not shrink below average spacing 1.05 tiles (0.4~1), arrival radius ≥ √(n·1.1/π).
- **Display**: inter-tick position interpolation (`Unit.RenderPrev` render only · not saved, `UnitRenderer.Alpha` = accumulated / SimDt), art direction hysteresis 12° (`ShownFacing` - prevents flicker at the due north · due south left-right flip boundary), the command wince display only when my unit is standing.
- **March fire command** (`src/Core/MarchCommand.cs`, `StepMarchFire` = after StepGapChecks): an officer (company officer -> officer within command range) every `marchDecideTicks` 10 ticks - 1/3 or more of members capable of march fire walking by a move command + officer suppression < 400 + visible enemies within the effective radius (+ spread ≤15) of the half-plane ahead of the center of mass -> `Company.MarchUntil = now + marchHoldSec` (1 s). Ends immediately on stopping. With no officer, the squad (`Squad.MarchUntil`): squad leader is an official NCO · members ≥ `marchNcoMinMembers` 3 · half or more walking · enemy within effective radius × `marchNcoRangeFrac` 0.6, judgement at 30-tick intervals. Infantry with no command = no march fire (`MarchCommanded`), vehicles (machine gun tanks · armored cars) are individual as before. Slowdown `MarchSlowed` = while commanded, everyone walking ×marchMoveMul (regardless of target · same tick). During march fire, an enemy within `marchChargeRange` 3 tiles of the edge -> that soldier auto-charges (`MarchCharge`, 10-tick interval; during a move command the charge target is fought with `Engage` and movement continues when the target falls). `chargeAutoRange` 1.5 -> **1**.
- **Save**: FormatVersion 19 - ORG_ company `MarchUntil` (after Holes) · squad `MarchUntil` (after members) · flag `SpeedMul` (after Spacing), included in the checksum. The measurement counter `World.Stats` (`MoveStats`) is not read by the simulation (not saved).
- **Attack-move does not capture trenches** (2026-10-19): `UpdateTrenchCapture` only for `UnitOrder.Move`, `SnapSlotsToTrenches(…, attackMove)` assigns nothing for attack-move (one man · formation · company all). If the arrival point is a trench tile, arrival handling (`TrenchOnArrive`) still enters. The tactical AI `LineDefend` trench move is `Ord.Move`.

### gapfill closing ranks - command · officer judgement · soldier skill (gapfill 대열 정비 — 명령 · 장교 판단 · 병사 숙련) (2026-10-19 user decision, branch `gapfill`, `src/Core/CloseRanks.cs`, test `Tests/GapFillSelfTest.cs` = `KD_SELFTEST_ONLY=gapfill`)
- **Background**: after N12, when vacancies were not filled at all during combat, in round 8 Korean wins 14 -> 10 · K/E 0.71 -> 0.82. Decision = fill during combat but **only by command**. The rest of N12 (25-second vacancy check when quiet · officer position · no chasing · scouts · arrival slack) unchanged.
- **① Player command** `CloseRanksCommand(Faction, Companies[])` (JSON `closeranks`, replay v10): card "대열 정비" (close ranks) hotkey **L** (command tab (1,2) -> (2,1) if occupied, combat tab (0,0)), the whole company of the chosen units. Execution = command tick `CloseAt`, valid until `CloseUntil` = + `closeWindowSec` 20, one immediate close-up + again every `closePassSec` 1 s (late-following soldiers).
- **One close-up** (`CloseRanksPass`): skipped if there is a flag (march · alignment) or frame behavior is in progress (next chance within the valid time). Ideal formation = `CompanyLayout.Build` with current members (N12 officer-behind placement), **center = median of soldier positions** (lateral · frontal axes) aligned to the slot median, corrected once by the median of the misalignment after assignment - using the center of mass would drag the whole column if only a few scatter. Idle soldiers (Idle · no group · not charging) who strayed more than `closeSlack` 1 tile from their slot are sent to the slot by a **move command** (`SendToSlots`, shared with the vacancy check - the vacancy check uses attack-move). Soldiers in a trench · at a trench spot excluded.
- **② Officer judgement** (`StepCloseRanks`, after StepGapChecks): `closeCheckSec` 6 s × `DecideInterval` (commander experience), company-Id staggered. Conditions = one of commander (not in handover) · same-faction officer · acting NCO + formation direction exists + no flag + no frame behavior + **in combat** (`CompanyInCombat`, when quiet the N12 vacancy check handles it). Indicators (`MeasureRanks`, officers excluded): ratio of soldiers who strayed more than `closeDispTiles` 2 tiles from the assigned slot ≥ `closeOnFrac` 0.35 · front-row empty slots (no soldier within spacing × `closeFrontTol` 0.75) ≥ `closeFrontEmpty` 3 · consecutive front-row empty slots ≥ `closeGapSlots` 3, any one -> alarm `CloseAlarm` on. Hysteresis: it turns off only when all three are below threshold × `closeHysteresis` 0.6. During the alarm the command interval is `closeCooldownSec` 20 (player commands count toward the interval too).
- **③ Soldier skill** (`SkillOf` = private rank): < `closeRegularRank` 2 recruit · < `closeVeteranRank` 4 regular · above that veteran (officers = treated as recruits). In combat (`EngagedForRanks` = a target or fired within `regroupFireSec` 5 s) follows immediately with probability `closeObey` [1, 0.5, 0.15], otherwise after `closeDelaySec` [0, 6, 12] s - immediately once combat ends. Roll = `PairNoise(soldier Id, command tick, seed)` (stateless). If not in combat, all follow immediately.
- **State**: per company `CloseAlarm` · `CloseAt` · `CloseUntil` (end of ORG_ `WriteCloseRanks`, checksum `HashCloseRanks`, Audit) -> **FormatVersion 27**. Measurement counters `Stats.CloseManual · CloseOrders · CloseMovers · CloseLate`. Golden `57126c0592bfb5cb 9ab507dab9134b3e` (on top of the ai412 merge).
- **Measurement** (TACTICS_OBS 'round 10'): officer judgement about 13 times per game · about 80 soldiers sent per game - in combat most companies are moving · attack-moving · in frame behavior · under a flag, so there are few close-up targets (idle soldiers). The disorder indicators of stationary companies in combat are almost unchanged (strayed ratio ≈ 0.66, front-row empty slots ≈ 16 - formations in combat are originally widely spread).
