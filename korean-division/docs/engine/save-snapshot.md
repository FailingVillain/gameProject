# Engine notes - save-snapshot (snapshot save/load and save compatibility) (엔진 노트 - save-snapshot (스냅샷 저장/불러오기와 저장 호환)) [split from ENGINE_NOTES.md 2026-10-23, body verbatim]

### Save / load (snapshot) (저장 / 불러오기 (스냅샷))
- **Controls**: in game F6 = quick save (`saves/quicksave.kds`), F7 = quick load, top [저장 F6] [불러오기 F7] buttons, commands `save [name]` · `load [name]` · `saves`. Autosave `autosave_1..3` (rotating) every 10 minutes (game time). Start screen [불러오기] page (name · date · map · play time · faction; broken/other-format files shown as '읽을 수 없음'/'호환되지 않음' (unreadable / incompatible), delete button). Save folder = `saves/` next to the executable; spectate and engagement tests are saved too (only impossible during replay playback).
- **Code**: `src/Core/Snapshot/` - `Snapshot.cs` (file format: header JSON + Brotli body, format version `Snapshot.FormatVersion`), `WorldSnapshot.cs` (World body write/read), `NavSnapshot.cs` (pathfinding cache), `ObjCodec.cs` (reflection-based generic serialization - AI controller state · pending commands; adding fields to the AI needs no save code), `SnapCtx.cs` (entity/group/path reference table · tombstones), `SnapMsg.cs` (error message Korean consts - for the font atlas). UI: `src/UI/SaveManager.cs`, `MainMenu.DrawLoad`, `Game.SaveGame/RequestLoad/AutosaveIfDue`.
- **Determinism rules (saves depend on them)**: ① pathfinding results depend on the cache, so store path objects · the flow-field list (LastUsed) · zone version · path serial number (the cost grid is recomputed on load) ② at the end of `World.Step` apply map changes (`RefreshPaths`) + `hashDirty = true` (tick-boundary invariant) ③ results must not depend on dictionary enumeration order (`Nav.NearestReachable`, `StandardAi.PickTarget` tie handling was made order-independent) ④ when adding a new state field, put it in the save and list it in `SnapshotSelfTest.Audit` (if forgotten, the test fails).
- **Policy**: different format version -> rejected (clear message). Different game version · different balance.json -> warn and load (rejected if a unit/building type vanished from the balance). The map is stored whole in the body, so changes to map files do not matter. When the state structure changes, raise `FormatVersion`.
- **Replay**: the replay of a game continued from a save contains only `StartSnapshot` (Base64) + the commands after it (`--verify-replay` works).
- **Verification**: `SnapshotSelfTest` (included in selftest, standalone `KoreanDivision --snaptest`; `KD_SNAP_QUICK=1` short, `KD_SNAP_ONLY=<part of name>`, negative control `KD_SNAP_BREAK=nav|ai`). `KoreanDivision --snapbench k=10500 pre=1200` = size · time measurement for 16 players 8000 units. Save file format: `"KDSV" u16형식 u32머리말길이 JSON u32원본길이 u64FNV u32압축길이 Brotli(본문)` (format u16, header length u32, JSON, original length u32, u64 FNV, compressed length u32, Brotli(body)).


## Save compatibility (저장 호환) (2026-10-22, branch `savecompat`)
- **Policy (pre-release)**: saves (`.kds`) and replays (`.kdr.json`) are opened **only when** `Snapshot.FormatVersion` / `ReplayFile.FormatVersion` is **exactly equal** to the current one. Old versions are rejected without conversion (we are in a development stage that raises the format version often, so no converter is maintained). The post-release compatibility policy (whether to migrate) is decided again at release time.
- Rejection is a reason message with no crash: `SnapMsg.OldFormat`/`NewFormat` ("이 저장은 이전 버전에서 만들어져 열 수 없습니다 (저장 형식 vN · 현재 vM)" = "This save was made by a previous version and cannot be opened (save format vN · current vM)"), for replays `ReplayVersionException.Make` (InvalidDataException + Data marker) + `SnapMsg.ReplayOldFormat`/`ReplayNewFormat`/`ReplayBroken`. Campaign saves are the same `.kds`, so the same path.
- Display: the load list shows a reason per entry (`SaveEntry.Error`), the replay list shows "(다른 버전에서 만든 리플레이 — 열 수 없음)" (replay made by another version - cannot be opened), and if startup fails `Program.cs` returns to the menu and shows the `S.StartFailed` notice on the first screen via `MainMenu.ShowMain(notice)`. In-game F7/load uses `ShowNotice(S.LoadFailed)`.
- The format number is checked before parsing the body (for replays only the JSON `Format` is read first - old files have different command kinds, so a full parse could blow up first). The sim path is not touched (only the load-failure path).
- Test: `KD_SELFTEST_ONLY=savecompat` (`SaveCompatSelfTest`) - old/new format headers, empty · truncated · random-byte saves, and empty · truncated · garbage replays fail only with SnapshotException / InvalidDataException.
- **Campaign save (`campaign.json`)**: `CampaignState.SchemaVersion` (currently 1, JSON `version`). Rule = fields are **add-only**; the new field's C# default is the value when it is missing from an old file, so old/partial files open without conversion and missing fields are filled with defaults (unknown fields ignored). When a field is deleted or its meaning changes, raise SchemaVersion and reject those old files. A larger version · broken file makes `CampaignState.Load()` return null + `LastLoadError` (Korean `SnapMsg.CampaignNewer`/`CampaignBroken`) - the campaign menu shows the reason and the notice "새로 시작하면 덮어쓰입니다" (starting new will overwrite it).
