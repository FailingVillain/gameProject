# Engine notes - terrain-environment (terrain · height · vision, weather, range · vision, forest, cover props) (엔진 노트 - terrain-environment (지형·높이·시야, 날씨, 사거리·시야, 숲, 엄폐물 소품)) [split from ENGINE_NOTES.md 2026-10-23, body verbatim]

### Terrain · height · terrain vision (지형 · 높이 · 지형 시야) (2026-10-19, ROADMAP ③ '지형 · 높이', `src/Core/GameMapTerrain.cs` · `FogVision.cs` · `FogOfWar.cs`, test `Tests/TerrainSelfTest.cs` = `KD_SELFTEST_ONLY=terrain`)
- **Terrain kinds** (appended to the end of `TerrainType` - byte values fixed): Forest · Rubble · House (impassable) · Wire · Trench. Values are in balance.json `"terrain"` (`TerrainRulesDef`), read on every query.
- **High ground** = a bool per tile (`GameMap.high`, `SetHigh/IsHigh`). Slope = a high tile touching flat ground in 4 directions. Structure info (forest depth = Chebyshev distance transform, beside-a-house 8 directions, slope, `TerrainHash`) is rebuilt by `EnsureTerrain` inside a lock on the first query after the terrain changes (not saved).
- **Movement**: `World.UnitSpeed` × `GameMap.MoveMul(pos)` (forest 0.7 · rubble 0.6 · barbed wire 0.3 · trench 1.0 · slope ×0.8). The flag (company anchor) also uses UnitSpeed, so the company slows together. **Barbed wire is currently impassable (`Terrains` Walkable=false, temporary 2026-10-19; does not block vision · line of fire)** - the movement multiplier · hesitation code remains but is unused. Wire hesitation = `Combat3.MaybeWireHesitate` (before MaybeHesitate, unarmored only, `wireHesitate*`).
- **Cover**: `Supply.CoverHitMul/CoverSuppressMul` = **the single best value** among the tile's terrain (`GameMap.TerrainCover`: forest · rubble · trench terrain · shell crater · beside a house) (no stacking; personal trenches deleted 2026-10-19). `World.CoverLevelOf(u)` (automatic grenade judgement) = on cover terrain. Height = in `Combat2.TerrainAccuracy`, high->flat ×1.15 · the opposite ×0.85.
- **Direct-fire line**: `GameMap.HasFiringLine` (weapon `los`, `Combat2.HasFiringLine` · `FindTarget` losFrom) = the old `HasLineOfSight` + deep forest on tiles in between (depth > `forestSeeDepth`) + a shooter on flat ground cannot fire beyond the first high tile. `HasLineOfSight` (movement · pathfinding) is unchanged.
- **Terrain vision** (`TerrainVision`, built from the map when FogOfWar first uses it, turned off by `vision.terrainBlocking`): recursive shadowcasting (8 octants, RogueBasin) over `vision.blockSize` (default 2) tile blocks. Block classification = at least half of 4 tiles: rock · house = blocking (visible), deep forest = blocking (only the block right next is visible), high-ground block to a flat-ground observer = blocking (visible). The result (block row intervals) is memoized by (origin block, radius, observer high-ground) - a pure function of terrain only, so deterministic, cleared whole if it exceeds the cap of 40000, not saved. Within the same update, vision circles with the same block · same or smaller radius · same high-ground flag are skipped (= company-level aggregation: a dense company costs only as many as the blocks it occupies).
- **Fog staggered update**: `FogOfWar.UpdateStaggered` (every tick of World.Step) - faction f re-stamps its own grid (`own[f]`) only when `(Tick − (f−1)·12/factionCount) % 12 == 0`. If there are allies, the visible grid `grids[f]` = max of own and allies' own (otherwise the same array). Save = own + building memory (`RebuildShared` on load). The renderer · last-seen display decide whether to redraw by `Fog.VersionOf(me)`. `Fog.Update()` (all factions immediately) is for start · cheats · tests.
- **Sight radius** `World.SightOf` = sightNear/Far × officer `vision.officerSightMul` (1.25, binoculars) × scout `scoutSightMul` (unit `"scout": true` - no such unit yet, a hook) × high ground `terrain.highSightMul` (1.25). Shared by fog · auto-target radius · own vision checks (deterministic).
- **Last-seen position** (`Render/LastSeen.cs`, display only): when a visible enemy unit leaves vision, a team-color × mark stays at that spot, cleared when seen again, dead, or after 45 seconds. The AI does not use it.
- **Map json**: `paint[].terrain` = grass · dirt · sand · water · rock · forest · rubble · house · wire · trench, height only = `"high"`/`"low"`, or `"high": true` together with terrain. Paint rect · circle · **tiles** `[[x, y], ...]`. Example `assets/maps/terrain_demo.json`. For generated maps, `SprinkleForestsAndHills` makes, per 18-tile grid cell by hash, forest 20% · hill 18% blobs (grass · dirt tiles only, excluding 12 tiles around the start point and near facilities, 180° symmetric for 2 players).
- **Rendering** (2026-10-19 tile integration): `MapRenderer` art slots NS = terrain NT + derived (forest edge · deep forest · grass high ground · 10 trench pieces), `BuildSlots` decides per tile at the first `EnsureSources(0)` - forest = deep if all 8 directions are forest, else edge; trench = 4-direction trench neighbor mask (T · cross · isolated replaced by horizontal); grass high ground = `high_ground` (other high ground is a bright tint). High-ground edges touching flat ground = `high_ground_rim_<n|e|s|w>` alpha overlay (`ShadeHigh`; old brightness line if the theme lacks it). House · rubble · barbed wire = `house` · `rubble` · `barbed_wire`. If the theme lacks a name, falls back to that terrain's art · procedural tile. Generation = `python tools/make_kd1920_terrain2.py --install` (the default 5 types are `make_kd1920_terrain.py`). For screenshots `KD_CAMPOS=<tileX>,<tileY>`. Minimap high ground is bright. 'High ground' shown in mouse info.
- **Save · checksum**: FormatVersion 10 (map high-ground array, fog own grid). `Map.TerrainHash` in the checksum. The old engagement tests (Aim · Combat2 · Combat3) run on a field with the forests · high ground of the generated map stripped out via `TestDefs.Flat`.
- **Measurement** (`--stress ABC k=10000 ticks=600`, 16 players 280²): Fog section ms/tick before -> after A 0.36 -> 0.40 · B 0.30 -> 0.46 · C 0.22 -> 0.26 (target ≤ 0.5 met, no multithreading needed). Staggered update lowered p99 A 13.2 -> 10.1 · B 17.3 -> 16.2 ms. Because of the memo, heap B +19 -> +40MB, allocation 5 -> 33KB/tick (B: squads keep moving to new blocks).

- **Building art (건물 그림) (2026-10-19)**: captured sites (metropolis · city · village) = `village-capture` LOD sheet (column 0 = neutral · column 1 = owned: team-color flag), if `LodSprite`, `BuildingRenderer.DrawSprite` draws with `LodDraw.Cell` at the center of the building footprint (flag frame if `curOwner` ≠ 0). Size = theme.json entry `scale` = 0.25 × building tile count / 8 (art footprint 8 tiles -> city 4 tiles · village 3 tiles). Capture ring · gauge · selection frame · contested marker unchanged. Theme keys `building.city|metropolis|village`. Terrain `house` tiles = when zoomed in (`MapRenderer.Lod64Zoom` or above), `building_art.house.<thatch|tile|brick|barn>` chosen by tile hash is overdrawn at the tile center (`BuildingRenderer.DrawHouses`, the terrain tile as is if the theme lacks it). Import = `python tools/import_kd1920_buildings.py` (idempotent; `import_kd1920.py` rewrites theme.json, so rerun after it). For screenshots `KD_CAMZOOM=<zoom>`.
### Weather · time of day (날씨 · 시간대) (2026-10-19, ROADMAP '날씨 · 시간', `src/Core/Weather.cs` · `Render/WeatherFx.cs`, test `Tests/WeatherSelfTest.cs` = `KD_SELFTEST_ONLY=weather`)
- **State** `World.Weather` (`WeatherState`: Kind · Time · start values · schedule `List<WeatherEvent(Tick, Kind|-1, Time|-1)>` · Next · TimeStepTicks · Changes). It changes only in `StepWeather` at the very start of `World.Step` (right after FlushCommands, only on scheduled ticks · timeStep multiple ticks) and in `SetupWeather` before tick 0 (map · `--weather/--time` · tests, fog recomputed immediately). Save = `WTHR` section at the end of the snapshot (FormatVersion 11), checksum `HashWeather`, Audit `WeatherState`.
- **Effects** (balance.json `weather`, `WeatherDef` caches enum -> multiplier tables): `SightOf` = the existing multipliers (officer binoculars as `1 + (officerSightMul−1) × times[t].binocular`) rounded, then `WeatherSight` (× weather · time of day, floor `minSight`, product floor `minSightMul`). **Because it is rounded to an integer radius, the terrain-vision memo key (block, radius, high ground) stays valid** - when the weather changes it just uses a different radius key (test: grid after weather change = new world). Building vision `BuildingSight` and march-fire radius use the same multiplier. Hit `HitChance` × `WeatherHitMul` (before HitCap), movement `UnitSpeed` × `WeatherMoveMul`. Suppression · concealment detection probabilities unchanged.
- **Map json**: `"weather"` · `"time"` · `"timeStep"` (minutes) · `"schedule": [{ "at": minutes, "weather", "time" }]` -> `MapFile.WeatherOf(map)` (ConditionalWeakTable) -> applied by `CreateStandard`. Replay = header `Weather` · `TimeOfDay` (tick 0 values) + the map's schedule. Cost comparison with `--stress ... weather=fog,night`.
- **Display** (`WeatherFx`, after EndMode2D · before screen symbols, uses wall clock · random numbers = display only): time-of-day tint + four-edge gradient vignette, overcast · rain · snow · fog layers, 10 fog blobs, rain line / snow dot particles (proportional to screen size, cap 420 / 300, pushed by the camera movement so they look attached to the ground). `FogRenderer.ExploredAlpha` = per time of day (night 105, default 150). `Game.WeatherLabel` before the HUD top bar, `S.WeatherChanged` notification when it changes. Ambient sound = `Sfx.SetAmbient(key)` + `UpdateAmbient` every frame (no-op if sounds.json lacks the key).
- **Measurement** (`--stress AC k=5000 ticks=600`, 16 players 280²): clear day A 4.65 · C 9.45 ms/tick (Fog 0.36 · 0.27) -> fog · night A 4.33 · C 8.97 (Fog 0.24 · 0.21) -> rain · day A 4.40 · C 9.46. Cheaper when vision shrinks.
### Range · vision · map ×1.5 (사거리 · 시야 · 지도 ×1.5) (2026-10-19, ROADMAP §2-8)
- **Values**: weapon ranges · unit/building vision · `acquireRadiusCap` 32 · howitzer `shellSpeed 26 / flightMax 4` are all in balance.json. The hit curve (`AccuracyCurve`) is a distance/range ratio, so untouched.
- **Code**: `Engage.closeIn` exclusion = only emplaced + category `gun` (machine guns · anti-tank rifles also close in to 0.8). `AutoCharge` / charging an enemy underfoot = `AutoChargeAllowed` (suppression < `chargeAutoMaxSuppress`), state value `AutoChargeState` = 3 if the target is charging (counter-charge - `GaitMul` 1, no cavalry shock, ends with 1 if the target disappears, save byte unchanged · read check ≤3). `UnitSpeed` × `marchMoveMul` (MarchTarget ≠ 0; the flag follows the slowest member's speed, so the whole company slows). The tactical AI's 'long-range fire' criterion = rifle range × 1.25 (`TacticalAi.LongRange`, formerly fixed 20).
- **Map**: `Config.DefaultMapWidth` 150 · `TilesPerPlayer` 11250, `GameMap.NearBase` 16.5/28.5, circular layout inner village −19.5 · second ring condition 18. The coordinate conversion of fixed maps · sample missions was a one-off script (rect = corners ×1.5 rounded toward the map center, 1-tile-thick line · at · starts · circle center = round(1.5c + 0.25) - keeps 4-fold/2-fold symmetry, house tiles = a 1~2-tile blob per tile). `BattleSetup.Distance` default 60 (menu · quick engagement · `--balance sim` 60 / city 120).
- **City art**: theme `building.city/metropolis` scale 0.25 (8 tiles) · `building.village` 0.1875 (6 tiles). HUD = `BuildingRenderer.DrawPortrait` (LOD tile width fitted to the rectangle).
- **`--balance sim` tempo line**: `템포: 첫 사격 · A/B 50% 손실 시각 · 사격 거리 평균 (첫 100발)` (Tempo: first shot · A/B 50% loss time · average firing distance (first 100 rounds)).
- **Measurement** (infantry 200 vs 200, tactical AI, fog, seeds 1~4): open flat ground 50% loss (the side that broke first) 46~49 s -> 39~48 s, firing distance 14.4 -> 20.3 tiles (0.85 of range), first shot 6 s -> 8.4 s (start distance 40 -> 60). Trench holder B: attacker 50% loss 44~45 s -> 43~45 s (unchanged), firing distance 14.7 -> 21.2. Mixed (infantry 120 · machine gun 8 · anti-tank 4 · sniper 4 · infantry gun 2 · field gun 2 · howitzer 1 · FT 3) flat 50% loss 50~54 s -> 50 s, terrain 82 s -> 67~70 s, firing distance 14.5 -> 20.8. `--stress CE k=10000 ticks=600`: 280² C 14.9 -> 13.4 · E 34.8 -> 36.2 ms/tick (FindTarget E 25.6 -> 28.3), new default 424² C 12.9 · E 33.7.

### Forest combat (숲 전투) (2026-10-19, branch `forest`, test `KD_SELFTEST_ONLY=forest`)
- **Scout-team forest probing** (`Scouts.cs` `BuildProbe`, balance.json `scoutAi.forestProbe · forestProbeLook · forestProbeQuietSec · forestProbeExtra · forestProbeDeepBonus`): if there is forest (`ForestDepth > 0`) within `forestProbeLook` tiles ahead of the company (travel direction if active, else `Company.Facing`) and every member has had no engagement (`EngagedTick`, `Engaging`) · being hit (`LastFiredAtTick`) for `forestProbeQuietSec` seconds or more, then `ScoutCtx.Probe`, and if the company is standing (`!Active` - deadlock) the scout team is made active (not before the quiet seconds after sim start). If a scout sees an enemy directly (`ScoutSeesEnemy`), that scout's Probe is cleared. During Probe, `ScoutPickSpot` uses +`forestProbeDeepBonus` instead of deep forest −40, forest +20, reference point · return distance +`forestProbeExtra`. No state · save field added (a function of tick · member state · terrain, FormatVersion 30 unchanged). N22 hit-cover is at the very start of `ScoutThink`, so it still takes priority.
- **Forest concealment**: `terrain.forestSeeDepth` 2 -> 3 (shared by `TerrainVision` · `HasFiringLine` · `IsDeepForest`), `forestHit` 0.8, `forestSuppress` 0.85. Measured with `tools/bn_campaign/gen_forest.py` (`run.py --gen gen_forest`).

## F6 cover prop layer (F6 엄폐물 소품 층) (2026-10-20, props)
- Data `assets/data/props.json` (rules + types). Per type: cover (hit multiplier) · losBlock · radius · blocksMove · hp · destroyed (variant key). Implementation `src/Core/Props.cs` (PropDefs · PropLayer · World.Props), placement `src/Core/GameMapProps.cs` (ScatterProps: forest edge = tree clusters, field = rock clusters; a blocking rock only when the 8-direction neighbors can walk; 180° symmetric if mirror), rendering `src/Render/PropRenderer.cs` (assets/themes/kd1920/props, `python tools/import_props.py`).
- State: spot + blocking tiles are in the map (GameMap.PropSeeds · propBlock, end of MapSnapshot), hp · variant are in World.Props (WriteProps at the end of ORG_). A blocking rock keeps blocking even when cracked (fixed by the map, so no pathfinding refresh).
- Cover: among props within coverReach around the target + within the cone (coverConeDeg) toward the shooter, the single best one, not stacking with terrain cover and taking the better (Combat2.TerrainAccuracy). Indirect fire excluded. Suppression: in props2 the shooter direction is passed (`AddSuppression(..., from)` -> `SuppressCoverMul`), taking the better of the terrain suppression multiplier and the prop cover multiplier (props.json `suppressCover`; indirect · explosions have no direction, so excluded).
- Line of sight: if the firing line passes beside a prop (radius + losMargin), hit x (1 - losBlock), multiplied, floor 1 - losMaxBlock. Props near both ends excluded (the target's side counts as cover). Looked up along the line at 0.5-tile intervals in the tile grid (spatial hash).
- Damage: Explode -> PropLayer.Blast (only weapons with damage >= minShellDamage, distance falloff SplashFactor). F1 firing position (Contact.SpotScore) · hit-cover seeking (CoverSeek) use CoverHitAt (threat direction = target, else 12 tiles in the facing direction).
- Missions: `props: [{type,x,y}]` by hand, `propScatter: true` generator rule (2.5 tiles from forces · deployment zone · 4 tiles from reinforcements). Console for checking `props` / `props goto`. Measurement: the `[F6소품]` line of `--tactics-obs`.
- props2: all 13 of `assets/missions/*.json` have `propScatter: true` (no hand placement). Measured prop-cover fire ratio A 0.1-0.3% B 0.9-1.4% (0.1~1.4 by seed) C 0.3-0.5%.
### Cover prop density increase (엄폐물 밀도 상향) (2026-10-21, propdens)

- `MissionDef.PropDensity` (json `propDensity`, default 1) multiplies the cluster probability (clusterPct) and the field cluster probability (fieldPct) (cap 100). `PropCell` (json `propCell`, default 0) is the scatter tile size (0 = props.json `cell`). At defaults it equals the old results (detcheck golden match).

- Measurement (tactics-obs 600 s, seeds 1-3, cover ratio = prop-cover shots / shots at infantry targets): before 0.1-1.4% -> after 5.3-8.2% (3-mission average 5.3-6.8%). Prop count 50-150 -> 1190-1990. Exchange ratio (enemy losses / friendly losses, total): A 1.29 -> 1.06, B 1.05 -> 1.09, C 1.59 -> 1.69 (3 games per seed).

- Basis experiment: raising only density (up to the 100% cluster cap) stays at cover 1-3% - tile size decides the cluster count. Props are placed over the whole map and not concentrated at the front line, so the exchange ratio is within seed noise.
