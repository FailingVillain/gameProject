## 2. 하천이란 (지형 모델) — 제안

- **proposal** 하천 = 폭이 좁은 (1~6칸) 물 띠. 기존 `Water` (통행 불가 깊은 물) 와 **논리적으로 같은 종류**이고, 차이는 (a) 지도에서 `line` 으로 곡선 모양으로 그린다, (b) 곳곳에 건널 곳 (여울 · 다리) 이 있다.
- 새 지형 바이트는 최소로: **제안안 A (권장)** = 새 값 1개 `Ford` (여울) 만 enum 끝에 추가. 깊은 물은 기존 `Water`, 다리는 기존 관례 (`dirt` 덮기) 유지하거나 보기 좋게 `Bridge` 를 추가 (Q2). 이유: 새 바이트는 FormatVersion 증가 + 렌더 + 시험 비용이 있으므로 필요한 만큼만.
- 안 B: `Ford` + `Bridge` 2개 추가 (다리를 흙 대신 널빤지 모양으로, 폭 · 방향 렌더, 이후 "다리 파괴" 확장 여지). 안 C: 새 값 없이 `Water` + 타일 플래그로 여울 표시 (스냅샷 구조 변경이 더 큼 — 비권장).

### 2.1 깊은 물 · 여울 · 다리 — proposal

| 종류 | 통행 | 이동 | 엄폐 | 시야 · 사선 |
|---|---|---|---|---|
| 깊은 물 (`Water`, 현행) | 불가 (현행 유지) | - | - | 현행 유지 (6장) |
| 여울 (`Ford`, 신규) | 가능 (보병 · 기병 · 차량 전부, Q3) | 느림 (proposal: x0.6) | 없음 (1,1) | 막지 않음 |
| 다리 (`dirt` 덮기 현행 / 선택 `Bridge`) | 가능 | x1 | 없음 | 막지 않음 |

- 수치 (0.6 등) 는 가칭. balance.json `terrain` 블록에 `fordMove` 로 넣고 측정 후 결정 (기존 forest · rubble 수치와 같은 방식).
- 여울에서 사격 · 명중 보정 (불리 등) 은 **제안하지 않는다** — 로드맵에 없음 (Q4 로 질문).

## 3. 이동 · 엄폐 · 시야 영향 요약

- 이동: `GameMapTerrain.MoveMul` 의 switch 에 `Ford => r.FordMove` 한 줄. 경사 곱은 그대로. 장갑 차량 예외 여부는 Q3.
- 엄폐: `TerrainCover` 는 `_ => (1,1)` 이므로 코드 변경 없음 (여울 = 엄폐 없음).
- 시야 · 사선: 여울 · 다리는 `walkable` 이라 `ClearFor` 가 막지 않음 = 변경 없음. 깊은 물이 현재 사선을 막는 점은 하천에서 문제가 될 수 있음 (강 건너 사격) — 현행 동작을 측정으로 확인한 뒤 Q6 에 따라 처리.
- 제압 · 항복 · 퇴각: `Suppression.NearWater` / `Surrender` 가 물 근처를 "몰린 곳" 으로 취급 — 하천이 많아지면 의미가 넓어짐. 구현 카드 2에서 `Water` 만 (여울 · 다리 제외) 보도록 확인.

## 4. 길찾기와 기존 도하 AI가 요구하는 것

- 길찾기: 여울 · 다리는 walkable 이므로 기존 A* 에서 자동으로 "건널 곳" 이 됨. 이동 배수 0.6 이 경로 비용에 반영되는지 확인 (MoveMul 가 길찾기 비용에도 쓰이는지는 구현 카드 1단계 조사, 안 쓰이면 여울이 다리보다 선호되지 않을 뿐 — 허용).
- 도하 AI (`FindCrossing`): 지형 종류 무관, "못 걷는 띠 + 옆의 열린 구간" 만 봄. 따라서 **여울/다리가 있으면 자동으로 병목 (건널 곳) 이 된다** — 코드 변경 불필요가 기본 기대. 확인할 것: (a) 좁은 하천 (폭 1~2칸) 이 `minObstacle` 에 걸려 병목으로 안 잡히는지 (tactics.json 값, 조정은 데이터), (b) 여울이 넓은 열린 구간 (폭 > `maxLaneWidth`=10) 이면 "병목 아님" 으로 판정돼 일반 공격 — 이건 의도에 맞음, (c) 도하 AI 가 여울을 속보로 지날 때 이동 배수만큼 늦는 점은 `launch` 타이밍에 영향 (측정).
- **proposal** AI 가 "깊은 물 근처 퇴각 금지" 등 하천 전용 판단을 새로 갖게 하지 않는다 (로드맵 범위 밖).

## 5. 지도 파일 · 렌더 · 미션 훅

- 지도 json: rail 과 같은 `{ "terrain": "water", "line": [x0,y0,x1,y1,...], "width": N }` 형태 제안. 현재 `line` 은 1칸 폭이므로 **폭 지정 (`"width"`) 은 새 기능** — 1칸 선을 두껍게 하는 것이 단순 (정사각 확장). 여울: `{ "terrain": "ford", "rect": [..] }` 로 하천 위에 덮어 칠함 (다리를 dirt 로 덮는 현행 방식과 동일). 곡선은 `line` 꺾은선 여러 개로 근사.
- 렌더: `MapRenderer` Water 케이스는 이미 해안선 경계 처리 (line ~117, 656~) 가 있음 → 좁은 띠에서 깨지지 않는지 시각 확인. 여울 = 물 타일 위에 밝은 모래빛 + 잔물결 절차 오버레이 (RailRenderer 처럼 `FordRenderer` 또는 MapRenderer 내 분기, TerrainVersion 캐시). 흐름 방향 애니메이션은 **제안하지 않음** (정적, 요청 시 후속).
- 미션 훅: 새 트리거 없음. 기존 영역 (`area`) · `when.area` 로 여울 영역 메시지 가능 (yalu_crossing 이 이미 그렇게 함). 미션 목표에 "다리 점령/파괴" 는 범위 밖.
- 기존 미션 지도 (c0_02_yalu 의 물 8칸 + 흙 다리) 는 **변경하지 않음** (골든/측정 보존). 하천 쓰는 새 미션/지도는 사용자 요청 시.

## 6. 스냅샷 · FV(골든) 영향

- 새 지형 바이트 (`Ford`, 선택 `Bridge`) = 기존 지형 배열의 새 enum 값 → 새 상태 필드 없음, Audit 추가 불필요 (rail 과 같은 논리). 단 `Snapshot.FormatVersion` +1 필요 (rail 이 53 사용 → rail 병합 뒤 하천은 54, 병합 시 main 값 +1 로 조정). FV 예약은 ops/FV_RESERVATIONS.md 에 등록 필요.
- 골든 (detcheck): 기존 지도에 새 지형이 없으면 골든 불변이어야 함 (수용 기준). `MoveMul` 분기 추가는 기존 지형에 영향 없음.
- 지도 serialization: 지형 바이트 배열이라 `MapSnapshot` 변경 없음 (rail 선례).
- 스택 기준: **base = `rail` 브랜치** (enum 끝 값 Rail 다음에 Ford 를 붙이므로 병합 순서 의존). rail 이 먼저 main 에 들어가면 base 를 main 으로.

## 7. 사용자 질문 (8개 이하)

1. **Q1** 하천 "소형" 의 폭 상한은? (제안: 깊은 물 1~6칸. 현재 yalu 는 8칸.)
2. **Q2** 다리를 별도 지형 (`Bridge`, 널빤지 모양) 으로 둘까, 현행 "흙 덮기" 유지할까? (권장: 우선 유지, 필요 시 추가)
3. **Q3** 여울은 모든 병종 통과 (포 · 차량 포함)? 아니면 보병/기병만, 포 · 차량은 다리만?
4. **Q4** 여울의 이동 감속 외에 사격/명중 불리 · 피로 · 제압 보정이 필요한가? (제안: 이동 감속만)
5. **Q5** 깊은 물은 계속 완전 통행 불가인가, 아니면 수영 (보병만, 매우 느림 · 무장 불가) 허용? (제안: 불가 유지 — 새 규칙이라 요청 없으면 안 만듦)
6. **Q6** 강 건너 사격: 지금 물 칸이 사선을 막는지 확인 후, 하천 너머 사격을 허용할지 (제안: 허용이 자연스러움 — 강둑 교전이 도하 AI 의 핵심)
7. **Q7** 여울/하천을 쓸 미션 · 지도는? (기존 c0_02_yalu 수정 vs 새 미션 vs 지도 시험만)
8. **Q8** 장갑열차 카드와 같은 묶음/순서로 진행할까, 별개로 진행할까? (선로가 하천을 건너는 "철교" 는 이번 범위에서 제외 권장)

## 8. 시험 계획

- `KD_SELFTEST_ONLY=terrain` 에 하천 블록: ford 이동 배수, 통행 가능, 사선 불변, line 칠하기 (곡선), 저장 · 불러오기 체크섬 일치.
- 길찾기 시험: 하천 지도에서 여울/다리 경유 경로 존재, 깊은 물 비통과.
- 도하 AI: `KD_SELFTEST_ONLY=crossing` 회귀 + 여울이 있는 하천 지도에서 `FindCrossing` 이 건널 곳을 잡는지 단위 시험.
- 회귀: detcheck 골든 일치, snaptest 0 실패, tactics-obs/`--choke` 측정은 기준선(docs/BASELINE_CURRENT.md) 대비 불변 (기존 지도 무변경).
- 시각: 하천 지도 접촉 시트 (사용자 확인용, 이동 중 해안 경계).
