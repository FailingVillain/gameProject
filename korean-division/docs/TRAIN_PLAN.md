# 장갑열차 · 화물열차 분할 계획 (spec, 2026-10-22, 코드 없음)
출처: ROADMAP_LONG 6번 · ROADMAP_SHORT '장갑열차 · 화물열차'. 카드 T30a~e (korean-division/tasks/T30*.md).

## 확정 결정 (사용자, ROADMAP_LONG 6번 원문 요약 · 날짜 확인 필요)
- "슬슬 작업을 시작해보자": 장갑열차 = 조종 가능 유닛 + 미션 스크립트 이동 둘 다 (선로 위 전진 · 정지 · 후진, 야포 + 중기관총, 중장갑, 객차 단위 파괴).
- 화물열차 = 미션 목표 (호송 · 탈취 · 파괴). 선로 파괴 = 나중에 (1차는 선로 = 지형). 上 설계·구현 + 中 그림.
- 철도 지형 = 이미 브랜치 `rail` (T07, TerrainType.Rail 끝 바이트, FV53, MapFile "line" 칠하기).

## 기반 브랜치
- **`rail` 위 스택** (`t28-cover-forest` 아님). 이유: 필요한 것은 Rail 지형뿐. T28 은 엄폐물 군집화 · 숲 윤곽(플래그 기본 꺼짐)이라 열차와 무관하고, 얹으면 T28 검토가 끝나기 전까지 열차 카드가 묶인다. 철도 주변 소품(엄폐물)을 쓰고 싶으면 그때 T28 위로 재스택 = 질문 Q-A5.
- 스택: T30a(rail) → T30b(T30a) → T30c(T30b) → T30e(T30c). T30d(그림)는 코드 선행 없음, 문서 선행만 (규격 §A).

## 공통 설계 초안 (카드에서 확정 못 하는 건 질문)
- 열차 = 객차 N량의 순서열 (기관차 · 포차 · 기관총차 · 화차 …). 객차 = 객체 하나 (HP · 장갑 · 소유 세력, 공격 대상), 위치 = 선로 경로 위 호장(arc length) 오프셋 (선두 호장 s 에서 car i 는 s - Σ간격). 선로 위만 이동; FlowField/군집 이동 안 씀.
- 선로 그래프: Rail 타일 연결(결정적 BFS · 타일 인덱스 정렬 순). 분기/교차: 1차는 단선 + 미션이 준 경유점 순서로 경로 고정 (질문 Q-A2).
- 결정성: 실수 누적 대신 정수/고정 틱 단위 호장, 난수는 DetMath/PairNoise 만, 저장 필드 [SnapExt], 체크섬(WorldChecksum) · Audit · FV 반영.
- 조종: 새 GameCommand 한 종류 (열차 속도 명령: 전진 · 정지 · 후진, 목적 경유점), Replay 번호 +1. 스크립트 이동: MissionDef 에 경로 · 정차 사건 (기존 MissionAction 틀 확장).
- 하지 않는 것: 선로 파괴, 분기기 조작, 열차 AI(적 열차 자율 판단), 탑승/하차, 하천, 신규 경제/보급 규칙.
