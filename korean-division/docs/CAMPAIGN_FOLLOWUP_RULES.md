# 캠페인 후속 규칙 제안 (T42 설계 초안 v0.1, 2026-10-22, 작성 spec/Sonnet)

> 범위: `CAMPAIGN_HOME_DESIGN.md` §2(탭 6·7·9·12·14)와 §12(규칙 7·10·11·13)에 적혀 있으나 코드가 없는 항목의 **구현 방식 제안**.
> 모두 **제안** — 사용자 확인 전에는 확정 아님. 수치는 전부 TBD(임시값은 JSON 에 "임시" 표시, 밸런스는 0.3 에서). 새 메커닉은 질문(§7)으로만 올림.
> 스토리 세션과 겹치는 칸(군령권 · 훈장 · 전사자 명부 이름 · 이벤트 문구)은 **TBD(스토리)** 로 두고 내용을 쓰지 않는다.
> 버전: 0.2 (밸런스 이전) — 전투 시뮬 규칙 변경 · 수치 튜닝 · AI 행동 카드는 이 문서 범위 밖(0.3/0.4).

## 0. 현재 상태 (코드 확인: t38f-home-readonly-tabs 작업 트리, 저장 스키마 v3)
- 있음: `RosterCompany`(Strength · MaxStrength · Wounded · UnhealedOps · Available · Caliber · Regiment), `ManpowerState`(Recruits · Wounded · Reserve), `Flags`(heir_mood · cmd_favor), `History`(MissionRecord), `Units/Officers`(MissionResults.UnitLine = 계급 이월), `DebriefReport`(WoundedReturned · Dead · DischargedWounded · Looted* · ShellsFired), 부상 25% 복귀 · 치료 0.5/명 · 3작전 뒤 전역(규칙 3, T19b).
- 읽기 전용 화면(T38f): 12 부대 기록 · 5 장비 재고 · 3 편제 트리. T19d: 8 참모진(학파). 나머지 후속 탭(1 요약 외) 본문 없음.
- 사기 · 피로 · 포로 · 일수 · 훈련 필드는 **저장에 없음**. `StartKills` 로 사병 전투 중 진급은 이미 제거됨(ENGINE_NOTES 묶음 3) → 진급은 작전 사이 홈 처리만 가능.

## 1. 구분 원칙 — 데이터만 vs 시뮬 필요
| 항목 | 분류 | 이유 |
|---|---|---|
| 훈련 숙련 | **보류(장기)** | 사용자 Q4: MVP 제외 · 장기. 카드 없음. 필드명도 예약하지 않음 |
| 사기 · 피로 계정 | 데이터만 | 홈의 계정(작전 사이 증감 + 출전 가능 문턱). 전투 안 효과는 **시뮬 필요 → 범위 밖**(질문 Q1) |
| 부상 복귀 규칙 | 데이터만 (대부분 기구현) | 25% · 0.5 · 3작전은 있음. 남은 것 = 복귀자 배치 규칙(Q8) |
| 진급 | 데이터만 | 후보 산출 = 이월 `UnitLine` 전과 + JSON 문턱. 군령권 = TBD(스토리) |
| 포로 | 데이터만 + **측정 전용 통계 1개** | 장부 · 처리(송환/수용)는 홈 데이터. 포로 발생 수는 시뮬이 센다 — 항복(T31c, 기본 꺼짐)에 의존. `World.Stats.GunShots` 같은 측정 전용 → 체크섬 · FV 불변 원칙 |
| 일정 · 일지 | 데이터만 | 이벤트 이력 + 작전 일수 카운터 |
- 공통: 저장은 v3 위에 **키 추가만**(없으면 기본값 → v3 저장 자동 이행, savecompat 테스트). 스키마 정수 상향은 T42a 가 1회만(v4), 이후 카드는 같은 v4 에 키만 추가. 시뮬 · FV 무변경, detcheck GOLDEN 불변이 수용 기준.

## 2. 사기 · 피로 (T42a)
- 대상 = 중대(`RosterCompany`) `Fatigue` 0..100, `Morale` 0..100 (대대 값 = 소속 중대 평균, 표시용).
- 증감 시점 = 작전 정산(`CommitResult`) 한 번: 투입한 중대 피로 +x, 투입 안 한 중대 −y, 사기 = 승패 · 손실률로 ± (함수 형태와 수치 TBD, `campaign_economy.json` 에 "임시" 로).
- 효과 = **출전 가능 문턱만**(피로 ≥ 문턱이면 '지침' 표시 + 투입 경고, 강제 잠금 여부는 Q1). 전투 안 사기 · 후퇴 문턱 연결은 이 카드 밖(0.3 후보).
- 화면 = 탭 1 사단 상태 요약에 사기 · 피로 평균 한 줄 + 탭 3 편제 트리 행에 막대(T38f 위에 읽기 표시 추가).
- 훈련과 분리: 피로 회복은 '쉼'(미투입 작전 수)로만, 훈련 효과 없음.

## 3. 진급 (T42b)
- 후보 = 이월 `UnitLine` 중 전과(킬 · 생존 작전 수 · 부상 복귀)가 문턱 이상. 문턱 · 계급별 정원 = JSON, 값 TBD(Q3). 장교 상한 = 중령(`officers.maxPromotionRank`, 기존 결정).
- 탭 9 진급 · 군령권: 진급 후보 목록 + [진급] 버튼(작전 사이에만) + 적용 결과 `History` 기록. **군령권 = TBD(스토리)** — 이 카드에서 만들지 않음, 탭 자리 문구만.
- 전투 안 자동 진급 부활 없음.

## 4. 포로 (T42c, 선행 의존 있음)
- 장부 `Stock.Prisoners`(정수, 세력별 키 가능) + `DebriefReport.PrisonersTaken`. 발생 수 = 항복(T31c, 0.4 로 미뤄 기본 꺼짐) 통계에 의존 → 항복이 꺼져 있으면 0. 카드는 '자료 통로 + 처리 화면'까지, 발생 빈도는 건드리지 않음.
- 처리 = 탭 7 외교: **송환 / 수용**(수용 = 보급품 소모 · 민심 항목은 추후). **편입(병력화)은 새 메커닉 → Q4 확정 전 구현 안 함.**
- 노획과 별개 장부. 수치 TBD.

## 5. 일정 · 일지 (T42d)
- 탭 14: 이벤트 이력(기존 `campaign_events` 발동 기록 + 작전 결과) 연표 + `Day`(작전 일수) 카운터. 계절 · 시간 규칙은 규칙 7 대로 **추후**(카운터만, 효과 없음). 일수 증가 폭 = 미션당 1일 vs 미션 데이터 `days`(Q6).
- 탭 12 부대 기록 확장 = 일지 줄 추가만. 전사자 명부(이름) · 훈장 = TBD(스토리) — 필드 예약하지 않음.

## 7. 질문 (≤8, DECISIONS_PENDING.md 에도 등록)
1. 피로/사기 효과를 **홈 출전 문턱까지만**(권장 · 시뮬 무변경) 할지, 전투 안(후퇴 문턱 등)까지 넣을지 — 후자는 시뮬 · 0.3 밸런스.
2. 피로 증감 수치와 문턱을 직접 주실지, 임시값("임시" 표시)으로 구현하고 0.3 에서 정할지.
3. 진급 문턱: 사병도 작전 사이에 킬/생존 작전 수로 진급하는가(권장: 장교 + 상사급까지만?), 문턱 수치.
4. 포로 처리 중 '편입'(병력화)을 허용하는가 — 새 메커닉이라 MVP 는 송환 · 수용만 권장.
5. 포로 발생원 = 항복(T31c, 0.4) 의존. 그때까지 T42c 는 통로만 만들고 값 0 으로 두어도 되는가.
6. `Day` 증가: 미션당 1일 고정 vs 미션 JSON 에 `days` 추가. 계절은 계속 추후로 두는가.
7. 스토리 의존 항목(군령권 · 훈장 · 전사자 명부 · 이벤트 문구)은 스토리 세션 결과가 나올 때까지 필드 없이 비워도 되는가.
8. 부상 복귀자는 원래 중대로 우선 배치(권장) vs 병력 풀 합산 — 현재 구현 동작은 T42a 착수 때 확인해 문서에 기록.
