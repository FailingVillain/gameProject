## 2. 권장 목표 수 (사용자 확정 수를 전제로 색 변형 수 제안)
### 2.1 기본 42종 (확정)
한국: 초가 6 / 기와 9 / 헛간·외양간 4 / 주막·객주 2 = 21. 만주·중국: 토벽·벽돌 10 / 기와류(청기와·회색기와 등) 5 / 토담 농가 3 / 헛간 3 = 21.
발자국 클래스: 3x3, 3x4, 4x4, 긴 3x5 (+주막/객주 큰 집은 4x4). 종마다 발자국 하나를 정하고 `CellFit` 이 오차를 흡수. 기본 42종 분배 제안: 3x3 ≈ 16, 3x4 ≈ 14, 4x4 ≈ 8, 3x5 ≈ 4. 담장·마당 소품은 별도 소품 (지금 범위 밖; PropRenderer 쪽으로).
### 2.2 색 변형: 구워 넣기 vs 그릴 때 곱하기
- **그릴 때 곱하기 (메모리 0)**: `DrawTexturePro` 의 tint 로 전체를 ±8~12% 명도·약한 색조 이동 (결정적 해시로 3단계). 지붕/벽 따로 색을 못 바꿈 (전체 곱셈). 팀 셰이더가 tint 를 다르게 쓸 수 있어, 집은 `TeamShader.Leave()` 후 일반 경로로 그려야 함 (코드 확인 필요 → 미검증).
- **구워 넣기 (재질 바꿔치기)**: `RUIN_MAP` 방식 재질 사상(roof/wall 팔레트)으로 같은 프리미티브를 다시 렌더 → 렌더 시간·아틀라스 메모리가 변형 수에 비례.
- 권장: 지붕 색이 정체성인 부류만 구워 넣고(기와류 2톤, 벽돌/토벽 2톤), 나머지는 곱하기로 때운다. **구운 변형 수 = 초가 1 · 기와(한국) 2 · 헛간 1 · 주막 1 · 토벽·벽돌 2 · 청/회 기와 2 · 토담 1 · 헛간 1.**
  - 한국 = 6·1 + 9·2 + 4·1 + 2·1 = **30 프레임**, 만주·중국 = 10·2 + 5·2 + 3·1 + 3·1 = **36 프레임**, 1차 합계 **66 구운 스프라이트** (+폐허는 6.3 참고).
- 좌우반전: 렌더 안 함 (3절 참고). 곱하기 3단계 × 반전 2 → 구운 66 × 6 = **396 조합**. 한 지도에 한 문화권만 쓰면 그 문화권 30~36 × 6 = 180~216 조합 → 지도에 보이는 집이 60~100채여도 이웃끼리 같은 모습이 거의 안 나온다. 이웃 중복 회피는 4.3 에서.

## 3. 메모리/아틀라스 예산 (42종 × 색 × 반전)
가정: 큰 발자국(3x3~3x5) 프레임 @128 ≈ 430~620 × 340~430 px ≈ 0.6~1.0 MB; 본체+팀+LOD 합산 프레임당 약 **2.0 MB** (기존 평균 1.6, 발자국이 커서 상향).
| 시나리오 | 계산 | 메모리 |
|---|---|---|
| 한 지도, 한 문화권, 구운 변형만 (폐허 제외) | 30~36 프레임 × 2.0 | **60~72 MB** (전 LOD), LOD0 만 약 45~54 MB |
| + 폐허 (기본종마다 1프레임, 21) | +21 × 2.0 | +42 MB → **약 100~115 MB** |
| 두 문화권 혼합 지도 (국경) | 66 + 42 | 약 **135~215 MB** |
| 반전을 구웠다면 (하지 않음) | ×2 | 위 값의 2배 — 불필요 |
- LOD0 상주 한도 768 MB 대비 최악(혼합+폐허 전부 상주) 약 28%, 한 문화권은 약 15%. 확대해서 동시에 화면에 들어오는 종만 올라가므로 실제는 더 적다. 업로드 한도 6 MB/프레임이라 새 구역 진입 시 종 30개(60 MB) 올리는 데 약 10프레임 — 비동기 빌드라 끊김은 낮을 전망이나 **미검증** (실측은 T55s 수용 기준).
- 절감책(필요하면): ① 집은 팀색이 필요 없으니 `_team` 평면을 만들지 않거나 R8 로 (현재 `_team` 이 RGBA 인지 R8 인지 코드로 확인 못 함 → 미검증; RGBA 면 약 절반 절감) ② 미션이 쓰는 양식만 로드 (3절 키 지연 로드가 이미 해줌: 사용 안 한 키는 안 올라감) ③ 폐허는 클래스당 공유.
- **좌우반전을 그릴 때 처리 (아틀라스 항목 추가 0)**: `LodDraw.CellFit` 안의 `Raylib.DrawTexturePro(tex, src, dest, …)` 에서 `src.Width` 를 음수로 주면 raylib 이 가로로 뒤집어 그린다 (CellFit 은 이미 src 사각형을 직접 만든다). `mirror` 불리언을 `CellFit` 에 선택 인자로 추가하면 끝. 앵커가 프레임 중앙(가로 대칭)이라 `dest` 계산은 그대로. 주의: ① 조명이 고정(좌상단)이라 뒤집으면 그늘이 반대쪽 — 작은 집에서는 거의 안 보이나 사용자 시트 검수 항목에 반전 쌍을 넣는다 ② 굴뚝·툇마루 같은 비대칭이 뒤집혀도 무관 ③ 인접 칸 병사와의 겹침 없음(사각형 동일). 팀 셰이더 경로의 4번째 인자도 동일하게 음수 폭 지원 여부는 **미검증** (집은 팀색 없으니 일반 경로로 그리면 문제 없음).
- 폐허: T39i 의 `ruins.py` 가 재료 사상 + 무너진 벽 프리미티브. 생성기(4절)에는 `ruin=True` 를 같은 파라미터에서 파생(벽 일부 높이 절단 + 지붕 붕괴 + 잔해)하도록 넣는다 → 기본종마다 폐허 1프레임 (구운 변형과 무관, 'a' 변형의 두 번째 칸). 폐허 b 2변형은 T39i 가 승인되면 클래스당(초가/기와/벽돌/토담) 유지.

### 4.2 구조
- `housegen.build(spec, ruin=False, palette=None) -> prims` : 기존 `B/slope/blob/post/rod/jars/rubble` 헬퍼만 조합 (새 렌더 코드 없음). `bbox` 는 스펙에서 자동 계산(`frame_for`). 이름 규칙 `ko-cho-01`, `ko-giwa-03`, `ko-bar-02`, `ko-inn-01`, `zh-mud-04`, `zh-giwa-02`, `zh-bar-01` … (+팔레트 접미 `-a/-b`).
- `housegen_specs.py`: 42개 스펙 표 (손으로 정함 — 무작위 생성이 아니라 "파라미터 사전" 이라 사용자 시트 검수가 가능). 기존 4종은 그대로 두고(회귀 방지) 스펙에서 재현되는지 대조용으로 `ko-cho-00` 등으로 비교 시트를 만든다.
- `make_building.py` `registry()` 에 `housegen.REGISTRY` 합치기 + `--set ko|zh|all` 필터 + `--shard i/n` (유닛 쪽 샤딩과 같은 방식).
- **한계/위험**: 곡선 처마·팔작지붕은 현재 `slope` 판 조합으로 근사 (`_curved_roof`); 모서리 접합이 박스 겹침으로 거칠 수 있음 → 지붕 형태 6종은 T55g 의 첫 시트에서 사용자 승인받고 스펙 42개로 진행.
### 4.3 렌더 비용 (**실측 2026-10-22, T55g, 부하 중 PC: 헤비 9/12**)
`make_building.py <id> --set proto` 한 집 = 상태 2개(intact+ruined) × LOD 3단 + 접촉 시트. LOD0 프레임 496x444 ~ 744x408 (3x3 ~ 5x3), 프리미티브 약 40~110개.
| 집 (발자국) | LOD0 | LOD1 | LOD2 | 합계(2상태·3LOD) |
|---|---|---|---|---|
| 초가 3x3 | 5.0 s | 1.2 s | 0.3 s | 6.5 s |
| 토벽 3x3 | 3.2~5.3 s | 0.8~1.0 s | 0.2 s | 4.3~6.6 s |
| 긴 5x3 | 5.5 s | 1.6 s | 0.4 s | 7.5 s |
| 팔작 4x3 | 9.4~11.2 s | 2.3~2.8 s | 0.6~0.8 s | 12.3~14.9 s |

- 평균 **집 1개(스프라이트 1종, 2상태·전 LOD) ≈ 10 s, 최대 약 20 s**. 상태 1프레임당 약 5 s (가정했던 0.5~1.3분의 약 1/10).

- 6.1 일정의 "샤드 8프레임 6~10분 × 14개"는 "집 8~10종 ≈ 2~3분 × 7개" 수준으로 줄어든다 (T55a/b 가 갱신).
- 현재 구조(위 4.2 의 `housegen_specs.py` 표는 JSON 으로 바뀜): `tools/buildings/housegen.py` + `tools/buildings/house_specs/*.json` (스키마 `HOUSEGEN_SCHEMA.md`, 팔레트 `_palettes.json`, 런타임 틴트 `_tints.json`). 샘플 시트 `docs/art_review/housegen_proto.png`.

## 5. 선택 로직 변경 (렌더 전용, 시뮬 무영향)
- 새 데이터 `assets/data/house_styles.json`: `{ "korean": { "classes": { "choga": {"w":3,"keys":[…]}, "giwa": …, "heotgan": …, "inn": … }, "footprintBias": {...} }, "manchu": {…}, "mixed": { "korean":0.5,"manchu":0.5 } }`. 클래스 가중치는 발자국 모양(정사각/가로/큰 건물)별 표.
- 미션 json 에 `"houseStyle": "korean|manchu|mixed"` (생략 시 기존 4종 `legacy` 동작 = 회귀 없음) — `MissionDef` 에 문자열 속성 1개, **체크섬·스냅샷·세이브에 넣지 않는다** (렌더 전용; `Snapshot.FormatVersion` 불변). 지도 파일에 `houseStyle` 도 허용(지도 단위 기본값), 미션이 우선. 구역 혼합(`mixed`)은 지형 좌표 기준 영역 지정이 필요해 1차에서는 가중치 혼합만, 영역별 지정은 T55s 범위 밖(제안만).
- 결정적 선택: `HouseBlocks` 캐시 빌드 시 (지도 한 번, 지형 버전이 같으면 재사용) 블록 순서(위→아래, 왼→오른)로 한 번에 배정. `pick = Hash(p.X,p.Y,salt)`; 종 → 구운 변형 → tint(0..2) → mirror(bit) 를 해시 비트에서 차례로 취함. **이웃 반복 회피**: 왼쪽·위쪽에 이미 배정된 조각과 같은 (종,변형) 이면 salt 를 올려 최대 3회 재시도. 순서가 고정이고 해시만 쓰므로 결정적, 화면 컬링과 무관(화면 밖 조각도 배정). 벽시계·딕셔너리 열거 금지 준수.
- 코드 접점: `BuildingRenderer.DrawHouses` + `HouseBlocks` (캐시에 `Piece` 선택 결과 추가) + `LodDraw.CellFit(mirror, tint)` + 테마 키 확장 (`building_art.house.<style>.<id>[ .a/.b]`) + `Theme` 가 가진 키 목록 조회. 키 수 66 → theme.json 이 커지므로 `building_art.houses` 묶음 항목(키 접두사 규칙으로 일괄 등록)을 도입할지 T55s 에서 결정 (theme.json 은 이미 1800줄; 키 하나당 6줄 → +400줄; 허용 한도는 ops/LIMITS.md 에서 확인 필요 → 미검증).
- 잔해 칸 폐가(`h%4`)도 같은 양식 풀에서 폐허 프레임으로 교체.

### 6.1 렌더 레인 일정 (유닛 재렌더를 굶기지 않기)
- 헤비 작업 동시 2개 한도: 집 렌더는 **항상 1프로세스만**, 유닛 재렌더 레인이 그 사이에 1 이하일 때. 시작 직전 `heavy_gate.ps1 -Render`. 샤드 = 8프레임(약 6~10분) 단위, 샤드 사이에 게이트 재확인 → 유닛 샤드가 대기 중이면 집 샤드 건너뜀.
- 순서: ① T55g 실측(스펙 1개, 약 1분) + 비교 시트 소량 ② 승인 후 T55a 샤드 4개(한국 66 프레임 중 한국 51 → 샤드 6~7개) ③ T55b 샤드 7~8개. 총 약 14 샤드 × 8분 = **약 2시간 분량**을 야간/유닛 레인이 비는 틈에 분산 (하루 3~4 샤드 정도면 며칠 안에 끝나도 유닛 재렌더 지연 0).
- 검수 시트: `docs/art_review/house_variety_ko.png`, `house_variety_zh.png` (문화권별 격자: 행 = 클래스, 열 = 종, 각 칸에 기본/구운 변형/반전쌍/폐허, 줌 3단계 중 LOD0·LOD2), + 지도 모의 배치 시트(한 문화권 12x8 블록에 양식 선택 로직 적용, 60~100채 모습) = `house_variety_map_*.png`. 게임 창 캡처 1장은 `tools/agent/run_game.ps1` 로만.

## 7. 미검증 / 모르는 것
- 렌더 시간은 T55g 에서 실측함 (4.3). 프레임당 메모리 2.0 MB 는 아직 가정이지만 4x4 LOD0 프레임이 624x540 으로 가정 상한(~620x430)보다 높이가 커서 메모리는 약간 상향될 수 있음.
- 프레임당 메모리 2.0 MB 는 기존 4종 크기에서 외삽. 팀 평면이 RGBA 인지 R8 인지, `LodAtlas` 가 팀 평면을 별도 페이지로 두는지 확인 못 함.
- 음수 폭 src 로 반전하는 것이 `TeamShader.Enter()` 경로에서도 정상인지, tint 가 팀 셰이더에서 어떻게 쓰이는지 확인 못 함 (집은 일반 경로로 그리면 되는 설계).
- theme.json 키 수 증가(+66) 가 ops/LIMITS.md 한도 안인지, `Theme` 로드 시간(레이아웃 json 198개 파싱)에 영향이 있는지 미확인.
- T39i 폐허 시트는 사용자 검수 전이며, 승인 전엔 ruins.py 를 기준으로 쓰지 않는다. 브랜치 팁은 66d6b95 (6e561df 는 그 부모).
- 생성기가 실제로 "서로 다른 집" 으로 보이는 정도 (지붕 6형 × 재질) 는 시트를 봐야 안다; 유사해 보이면 스펙 수를 줄이고 디테일(문·창·부속) 가짓수를 늘린다.
